任务行悬停「删除」· 平滑切换三方案

问题：hover 出现删除按钮时，日期与「逾期」标签被瞬间顶开（flex 布局重排无过渡）。
操作：把鼠标移入下方各行，再移出——对比「日期/逾期是否被顶动」「按钮出现方式」。 建议每行多走几遍（快速往返更能暴露抖动）。基线建议 --t-ui: 180ms ease-out，遵循 prefers-reduced-motion。

现状（问题本身）

display: none ↔ inline-flex——右侧内容一瞬间被顶开，无过渡。
做方案 A 的 demo 给用户选 2026-09-12 逾期

A 常驻透明占位

按钮始终占位（透明），hover 只淡入——内容永不被顶；代价是每行右侧固定留出按钮宽。
做方案 A 的 demo 给用户选 2026-09-12 逾期
优点：零布局位移、零闪烁，实现最简（仅 opacity 过渡）；确定感强（按钮位置稳定，可及性：键盘焦点可用）。

B overlay 悬浮滑入

按钮浮在行右端（absolute 不占位），hover 滑入（淡入+右移 6px）。日期区右侧预留 60px 缓冲避免被盖死。
做方案 B 的 demo 给用户选 2026-09-12 逾期
优点：内容横向完全不动，按钮进入有明确滑动方向；缺点：悬浮罩层可能盖住日期尾部（已用缓冲缓解），行内元素层级需管理。

C 宽度平滑让位

按钮 max-width+opacity 过渡展开（0→72px），日期/逾期被连续平滑挤开——保留"让位"的信息感，布局全程连续。
做方案 C 的 demo 给用户选 2026-09-12 逾期
优点：保留"顶开"的因果可见性；缺点：布局动画开销较大（行内文本重排），快速往返 hover 时日期/逾期会连续摆动，长行文案也可能被挤动。
