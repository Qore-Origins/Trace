# 修复树拖拽松手弹回原位：movePlan 乐观更新

**类型**：fix
**日期**：2026-09-07 23:05
**影响范围**：src/renderer/src/components/tree-utils.ts、src/renderer/src/stores/tree-store.ts、src/renderer/src/components/PlanTreePanel.tsx、test/tree-utils.spec.ts

## 变更描述

用户反馈（dev 实测）：拖拽松手后被拖行立即弹回原位，IPC 回来后才跳到新位置。根因：`movePlan` 为异步 IPC（fs 移动 + 双层刷新，约 50-300ms），期间 dnd-kit 已复位 transform 而 `childrenMap` 仍是旧数据 → 先弹回、后跳位两段式闪烁。

## 修改详情

- [tree-utils.ts]：新增 `optimisticMove` 纯函数——松手瞬间本地先行换位：旧父层移除 + 新父层插入 + 已加载子树键/路径前缀整体迁移；插入位按父级顺序载体现实（顶层/计划父级=children_order 精确索引；纯文件夹=zh-CN name-sort，与主进程 treeGetChildren 排序一致，避免权威刷新后二次跳位）；空文件夹接收首子项时目标行 has_children 置真（否则 flattenTree 不下钻、乐观行不可见）；不可应用（节点不在已加载视图）返回 null
- [tree-store.ts]：`movePlan` 改乐观流程——快照 → `optimisticMove` 应用（含选中/展开键迁移、目标父层乐观展开）→ IPC；失败整体回滚快照 + `message.error`（顺带修复既有缺陷：原实现 `void movePlan(...)` 失败为无提示的未处理 rejection，如拖入同名冲突时静默无反馈）；返回 `Promise<boolean>`
- [PlanTreePanel.tsx]：`onDragEnd` 接布尔返回，成功才补展开目标父层（读 `getState().expandedKeys` 最新值，防闭包过期重复追加）；删除前置 isSelfOrDescendant 分支（store 统一拦截，返回 false）
- [tree-utils.spec.ts]：optimisticMove 8 例（同父重排精确索引/跨父入计划/入文件夹 name-sort/文件夹内重排原位/未加载目标不预插/子树键迁移/空文件夹置真/不可乐观返回 null），105 测试全绿

## 影响分析

- 体验：松手即落定，无弹回；失败（同名冲突等）回滚 + 明确报错提示
- 数据一致性：乐观位与权威刷新位按构造对齐；`trace:plan-changed` 事件订阅与 refreshAround 的并发刷新幂等
- 已知边界（如实说明）：①纯文件夹内排序仍不持久化（无载体，按名排序——既有数据层设计，非本次回归；如需支持需引入文件夹元数据载体）；②跨父移动时被拖行 React key（path）变化，旧行卸载新行挂载，dnd-kit 拖拽已在 onDragEnd 结束后 flush，理论安全，需 dev 实测确认无残影
- 验证：typecheck + 105 测试 + build 全绿；建议 dev 路径——顶层拖 A 到 C 后松手（应立即落位不弹回）→ 拖计划入文件夹（行立即出现在文件夹内且自动展开）→ 拖入同名冲突文件夹（应回弹 + 红色错误提示）→ 重启确认顺序持久化
