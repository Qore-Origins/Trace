# Demo 折叠按钮失灵根治——路径/挂载点/组登记/重复渲染四处缺陷

**类型**：fix
**日期**：2026-09-08 12:10
**影响范围**：docs/prototype/tree-animation-demo.html

## 变更描述

用户实测：单个折叠按钮点击完全无效（不展开也不收拢），仅右侧「全部展开/全部收拢」有部分效果，且总控不驱动按钮动效。排查确认为四处复合缺陷，全部静默失败（无报错），本次根治。

## 修改详情

- [tree-animation-demo.html]：
  - 缺陷1（根路径）：assign 给根分配 path='计划库（源头）'，而 expanded/pathToGroupEl/slotInnerOf 均以 '' 键根 → 根按钮全链路失效。修复：根固定 path=''（isRoot 参数），顺带移除仅被错误代码引用的 byPath Map
  - 缺陷2（挂载点）：hostOf 将子组挂到「父行」的 slot-inner（应为自身行内）；且顶层节点 parentPath 用 slice(0, lastIndexOf('/')) 计算，无 '/' 时 lastIndexOf=-1 → slice(0,-1) 剁掉末字 → 查找失败 → expand 静默 return。修复：删除 hostOf，expand 直接 slotInnerOf(node)（自身行 slot-inner；根 → scroll）
  - 缺陷3（组未登记）：初始渲染的嵌套组只在 expand 路径登记 pathToGroupEl → 初始展开的「2026 冲刺」收拢时查不到组 → startCollapse 静默 return。修复：appendChildren 构建嵌套组时同步登记
  - 缺陷4（重复渲染）：appendChildren 遍历「含后代的扁平列表」同时又嵌套递归子组 → 初始屏 Q3/发布清单/调研 渲染两遍且缩进错乱。修复：只遍历直接子项（node.children），嵌套子树由各组递归渲染；删除不再使用的 revealedRows
  - 防御：「全部展开」对处于收拢途中的目标先 cancelCollapse 再展开，避免新旧两组并存

## 影响分析

- 单个折叠按钮、根按钮、级联总控三条交互路径全部打通；按钮动效（方框 +/- 旋转变号）随状态切换正常触发
- 波次节奏（D2/D3/D8）基于直接子项计数，语义更准确（此前按整棵揭示子树计数）
