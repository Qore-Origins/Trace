# Windows 根路径正斜杠导致后续计划操作被拒

状态：待修复；优先级：P2；发现：2026-09-23 v0.15.0 打包版隔离烟测。

## 复现

在 Windows 打包版通过 `app:setRootDir` 传入存在且可写的绝对路径，但使用 `D:/...` 形式。切库返回成功，界面显示库已配置；随后 `storage:createPlan` 可成功，`storage:appendComponent` 对新计划却返回 `PATH_UNSAFE`（11）。将同一目录以原生 `D:\...` 路径再次设置后，追加组件成功。

## 根因与影响

`resolveWithin(rootAbs, '')` 对空相对路径直接返回未规范化的 `rootAbs`，使主进程保存了正斜杠根路径；后续 `resolveWithin` 用 `node:path.resolve` 生成反斜杠绝对路径，再与原始根路径做字符串前缀比较，合法子路径被误判越界。当前原生目录选择器在 Windows 返回反斜杠路径，正常 UI 主路径未在本次烟测中复现；直接 IPC/未来 Agent API 输入会受影响。

## 修复建议与验收

在唯一的路径安全入口规范化根路径后再比较，保留越界拒绝；补 Windows 正/反斜杠根路径及 `..` 越界回归。修复前不要放宽 `PATH_UNSAFE` 检查。此问题未并入 v0.15.0 发布改动，后续单独修复并跑 typecheck/test/打包版回归。
