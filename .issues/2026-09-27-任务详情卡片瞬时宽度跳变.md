# 任务详情卡片瞬时宽度跳变

状态：已修复并完成浏览器与自动化验证；产品提交 `fda4972b1c9e148a614376769146d3ea8c6a3cca`；已纳入 v0.18.1 双平台 Release。

## 现象

用户补充了复现动作：任务详情中的任务取消勾选时，“逾期”标签出现，卡片有一瞬间的跳动。此前“预期”指“逾期”标签。用户要求同时检查是否存在类似布局问题。

## 根因与复现证据

`TaskDetailCard` 取消勾选时将 `done` 改为 `in_progress`；已过计划日期令 `isOverdue` 变为 true，标题行随即条件挂载“逾期”标签。`TaskListCard` 中的任务行使用同一条件挂载和同一 `.tag-overdue` 样式。

现有 CSS 将标签的 `max-width` 从 0 动画至 52px，同时动画内边距，且没有禁止换行。Chrome 逐帧测量显示：标签在中间宽度时折成两行，最终恢复单行。任务详情与任务列表的外框宽度始终不变；任务详情标题宽度变化 42px、任务列表任务名宽度变化 44px；两种卡片高度均短暂增加 14.56px，标题/任务行纵向位置短暂变化 7.28px。1200px 亮色和 720px 暗色均复现；减少动态效果可消除高度过渡，但仍有宽度瞬变。

测试入口：`node demo/frontend-foundation/overdue-layout-check.mjs 52831 52832`（独立 Chrome CDP 52831、内存 Vite 宿主 52832；无参数默认 52821/52822）。修复前真实布局稳定性断言按预期失败，6/6 场景均检测到同类变化。拖拽缩放、自动高度文本框和滚动条不参与本次复现。

## 修复

- 对计划日期已过的任务保留逾期标签布局槽位；完成态以透明度隐藏并标记 `aria-hidden="true"`，取消完成时淡入；不再对占宽和内边距做入场过渡。
- 标签设置 `white-space: nowrap`，从根源上禁止中间宽度折成两行。
- 任务详情与任务列表统一处理；非逾期任务不额外占位。共享日期资格判断不改变原 `isOverdue` 语义。

## 验证与同类检查

- 同一 Chrome 回归入口修复后 6/6 通过：任务详情与任务列表在 1200px 亮色、720px 暗色、720px 减动效的完成→取消→再完成全程，卡片外框、标题/任务名和标签尺寸/位置的逐帧变化均为 0；非逾期任务无标签槽位，无页面水平溢出。
- `npm run typecheck` 0 错；`npm run test` 40 文件、398/398；`npm run build` 成功（renderer 7,156 模块）。`git diff --check` 通过。
- 单选计划的逾期文案由日期决定，勾选状态不触发其挂载；心情/注释无逾期标签。样式检索未发现其他卡片占宽入场动画；树高度过渡属于独立的展开/收拢行为。
