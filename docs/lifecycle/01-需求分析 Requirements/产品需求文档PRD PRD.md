## 1. 产品概述 Product Overview

### 1.1 产品定位 Product Positioning

| 维度 Dimension | 描述 Description |
|-------------|----------------|
| 产品名称 Product Name | 溯源 Trace（· by Qore 叩心） |
| 产品类型 Product Type | □ Web □ Mobile App ☑ Desktop |
| 核心价值 Core Value | 计划有迹可循：文件夹即计划、五类组件渲染编辑、溯源查询找到源头 |
| 目标用户 Target Users | 个人用户（开发者本人）；远期扩展同类计划管理人群 |

## 2. 用户分析 User Analysis

### 2.1 用户角色 User Roles

| 角色ID Role ID | 角色名称 Role Name | 角色描述 Description | 使用频率 Usage Frequency |
|--------------|-----------------|-------------------|----------------------|

### 2.2 用户故事 User Stories

#### 故事1：作为个人用户

**用户故事模板 User Story Template:**

> 作为个人用户
> 我想要用文件夹树统一管理我的计划（新建、嵌套、拖拽）
> 以便于所有计划集中在一处、层级清晰、随时调整

**验收标准 Acceptance Criteria:**

- [ ] 我可以选择/切换计划库根目录，且数据以文件夹形式存放
- [ ] 我可以创建/重命名/删除计划文件夹（删除需二次确认）
- [ ] 我可以创建多级子计划（嵌套），并拖拽调整层级与顺序
- [ ] 嵌套/拖拽后的结构与磁盘文件夹结构一致（明文件验证）

**优先级 Priority:** P0

**预估故事点 Story Points:** 5 点

#### 故事2：作为个人用户

**用户故事模板 User Story Template:**

> 作为个人用户
> 我想要计划内容以"计划单片组件"渲染和编辑（单选计划、多选计划、任务列表、任务详情、注释）
> 以便于排版统一、编辑免 markdown 语法、所见即所得

**验收标准 Acceptance Criteria:**

- [ ] 5 类组件均可插入计划并正常渲染
- [ ] 点击组件可直接编辑，无需切换"编辑模式"
- [ ] 任务列表/任务详情组件支持三态状态更新（未开始/进行中/完成）
- [ ] 组件的渲染风格一致（同类型同构）

**优先级 Priority:** P0

**预估故事点 Story Points:** 5 点

#### 故事3：作为个人用户

**用户故事模板 User Story Template:**

> 作为个人用户
> 我想要对计划/任务/注释做关键词检索，并从命中项一键回到所属计划
> 以便于"找到源头"（溯源），复用历史经验

**验收标准 Acceptance Criteria:**

- [ ] 全局搜索可命中 计划名/任务内容/注释内容
- [ ] 命中项显示所属计划路径并可在打开计划后定位高亮
- [ ] 千级计划/万级任务规模下检索 ≤ 1s（M5 实测）

**优先级 Priority:** P0

**预估故事点 Story Points:** 3 点

### 2.3 用户旅程 User Journey

**旅程名称 Journey Name:** 计划闭环旅程（制定 → 执行 → 溯源）

| 阶段 Stage | 用户行为 User Action | 系统响应 System Response | 触点 Touchpoint |
|-----------|-------------------|----------------------|---------------|
| 发现 Discovery | 痛点认知 → 方案产生（2026-08-25） | 方案文档成文 | 方案文档 |
| 注册 Sign Up | 立项（2026-09-05） | 00/01 文档生效 | 本章程/文档集 |
| 使用 Usage | 打开应用 → 目录 → 计划 → 组件 → 任务 → 溯源 | 树/渲染/检索各模块响应 | 应用主界面 |
| 转化 Conversion | 长期使用（≥4 周）；数据沉淀为"个人计划资产" | 数据可迁移/备份 | 数据文件夹 |

## 3. 功能需求 Functional Requirements

### 3.1 功能架构 Feature Architecture

```
溯源 Trace（桌面应用）
├── 存储模块 Storage
│   ├── 计划库根目录管理（选择/切换，首次启动引导）
│   ├── 计划文件夹（创建/重命名/删除）
│   ├── 嵌套结构（子计划，多层）
│   └── 拖拽移动/排序（层级与顺序）
├── 页面渲染模块 Rendering
│   ├── 计划单片组件（5 类）：单选计划、多选计划、任务列表、任务详情、注释
│   ├── 组件内编辑（渲染即编辑）
│   └── 组件顺序管理（插入/删除/移动）
└── 溯源查询模块 Trace & Search
    ├── 关键词检索（计划名/任务/注释，本地索引）
    └── 来源回溯（命中项 → 所属计划定位高亮）
公共：本地文件读写、本地检索索引、异常与日志（01-4 功能规格展开）
```

## 5. 用户体验设计 UX Design

### 5.1 设计原则 Design Principles

1. **计划先行**：一切围绕"计划"对象——层级树 + 组件内容 + 溯源入口
2. **所见即所得（组件化）**：渲染即编辑，无 markdown 语法、无模式切换
3. **低认知成本**：树/面包屑/搜索三入口一致，30 分钟内上手
4. **本地优先与安全感**：明文件可备份，破坏性操作有确认，数据不出设备

### 5.2 信息架构 Information Architecture

```
应用主界面 App Window
├── 计划树（左栏）：根目录 → 计划文件夹 → 子计划（多级展开/收起）
├── 内容区（中/右栏）：当前计划渲染区（5 类组件序列 + 空态）
├── 全局检索（顶部）：溯源查询入口（关键词 → 命中列表 → 回溯）
└── 首次启动引导：根目录选择（一次性）
```

## 8. 业务规则 Business Rules

### 8.1 核心业务规则 Core Business Rules

| 规则ID Rule ID | 规则描述 Rule Description | 触发条件 Trigger | 处理逻辑 Logic |
|--------------|----------------------|----------------|--------------|
| BR-001 | 计划=文件夹 | 创建/移动/删除计划时 | 映射物理目录操作；删除需二次确认 |
| BR-002 | 内容仅 5 类组件 | 编辑计划内容时 | 枚举校验；未知类型降级占位 |
| BR-003 | 任务三态机 | 任务状态变更时 | 未开始↔进行中↔完成，允许回退；完成记时间 |
| BR-004 | 同级重名阻止 | 创建/重命名计划时 | 提示冲突，不创建 |
| BR-005 | 循环嵌套禁止 | 拖拽放置时 | 目标为自身/子孙 → 阻止 |
| BR-006 | 数据不出设备 | 任何操作 | 应用无网络功能（硬约束） |
| BR-007 | 破坏性操作确认 | 删除/切换根目录 | 显式确认弹窗 |

### 8.2 验证规则 Validation Rules

| task.title | 非空；≤200 | "任务标题不能为空" |
| task.status | 枚举三态 | "无效状态" |
| note.content | 非空；≤20000 | "注释内容无效" |

### 8.3 计算规则 Calculation Rules

| 计算项 Calculation | 公式 Formula | 说明 Notes |
|----------------|-----------|----------|
| 逾期判定 | planned_at < 今天 且 status <> done → 展示"逾期"标记 | 仅展示层，不回写状态 |

### 9.2 MVP功能范围 MVP Feature Scope

**包含 Included:**
- 存储模块：根目录管理、计划文件夹 CRUD、嵌套、拖拽
- 页面渲染模块：5 类组件渲染、组件内编辑（渲染即编辑）
- 溯源查询模块：关键词检索（计划/任务/注释）、来源回溯

**不包含 Excluded (v1.0后):**
- 撤销/还原（P1）、高级筛选（P1）
- 模板库、主题设置、导入导出、标签（P2）
- 登录注册/云同步/移动端/markdown 直接编辑（远期无计划项）
