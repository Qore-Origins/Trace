## 2. 业务背景 Business Background

### 2.1 业务现状 Current Situation

**当前业务流程 Current Process:**

```
计划产生（脑子/聊天记录）
  → 挑选载体（笔记 App / Markdown 文档 / 聊天置顶 / 任务 App）
  → 手工排版（格式随载体而异）
  → 执行（任务状态靠记忆）
  → 复盘（散落，无固定做法）
  → 溯源（翻找历史文档，经常找不到）
```

**存在的问题 Existing Problems:**

| 问题 ID Problem ID | 问题描述 Description | 影响范围 Impact | 紧急程度 Urgency |
|------------------|-------------------|---------------|---------------|
| P-001 | 计划排版乱：无统一结构，格式靠手工 | 全部计划 | 中 |
| P-002 | 集成管理差：计划分散≥3 载体 | 全部计划 | 高 |
| P-003 | 任务管理差：无状态、无归属 | 全部任务 | 中 |
| P-004 | 溯源/查询困难：历史来源找不回 | 历史计划全部 | 高 |
| P-005 | 计划编辑难：markdown/文档编辑成本高 | 全部计划 | 中 |

### 2.2 变化驱动因素 Change Drivers

| 驱动因素 Driver | 描述 Description | 影响程度 Impact |
|--------------|----------------|---------------|
| 市场变化 Market Change | 个人计划管理需求未被"计划语义"产品满足（竞品为通用笔记/任务工具） | 中 |
| 技术发展 Technology | 桌面框架（Tauri/Electron/Flutter）与本地索引能力成熟，自研成本低 | 中 |
| 竞争压力 Competition | 有（Notion 等），但差异化定位空缺 | 低 |
| 政策法规 Regulation | 无影响（本地应用） | 低 |
| 用户需求 User Demand | 用户（开发者本人）长期实践验证的需求，5 痛点明确 | 高 |

### 2.3 业务机会 Business Opportunity

**自用效率闭环 + Qore 作品线：**

1. **用户机会**：一个"计划语义"的单一入口工具——计划=文件夹、内容=五类组件、历史=可溯源；
2. **组织机会**：Qore 个人工具线首作（`Qore-Origins/Trace`，可开源），与组织口号「叩问本心，不忘初心」产品立意呼应（溯源=回到起点）；
3. **工具链机会**：零现金成本（本地、开源工具链、无服务器），个人时间投入为唯一成本。

## 6. 业务流程 Business Processes

### 6.1 核心业务流程 Core Business Processes

#### 流程1：计划创建与组织

**流程描述 Process Description:**
用户在计划库中创建计划（=文件夹），组织层级与内容（组件）。

**流程图 Process Flow:**

```
[开始] → [指定/使用计划库根目录] → [创建计划文件夹] → [嵌套子计划/拖拽调整] → [插入组件填充内容] → [结束]
```

**流程步骤说明 Step Details:**

| 步骤 Step | 操作者 Actor | 操作 Action | 输出 Output |
|----------|------------|-----------|-----------|
| 1 | 用户 | 确认计划库根目录（首次启动选择/后续切换） | 根目录状态 |
| 2 | 用户 | 创建计划文件夹（顶层） | 计划文件夹 |
| 3 | 用户 | 创建子计划文件夹（可多级）或拖拽调整层级 | 嵌套结构 |
| 4 | 用户 | 在计划内插入计划单片组件（单选/多选/任务列表/任务详情/注释） | 组件内容 |
| 5 | 系统 | 持久化到文件夹（明文件 + 元数据） | 磁盘数据 |

**业务规则 Business Rules:**

- 计划=文件夹；层级 = 文件夹嵌套（详见 §7）
- 同层级内结构以组件序组织（渲染顺序 = 文件内组件顺序）

#### 流程2：任务执行与追踪

**流程描述 Process Description:**
用户执行任务列表组件中的任务并更新状态。

**流程图 Process Flow:**

```
[进入计划] → [查看任务列表组件] → [更新任务状态] → [保存] → [进度可见]
```

**流程步骤说明 Step Details:**

| 步骤 Step | 操作者 Actor | 操作 Action | 输出 Output |
|----------|------------|-----------|-----------|
| 1 | 用户 | 打开目标计划 | 计划视图 |
| 2 | 用户 | 在任务列表/任务详情组件中查看任务 | 任务集 |
| 3 | 用户 | 变更状态（未开始→进行中→完成） | 状态变更 |
| 4 | 系统 | 持久化并刷新展示 | 最新进度 |

**业务规则 Business Rules:**

- 任务状态机：未开始 → 进行中 → 完成（可回退）
- 逾期为展示层判定（完成时间 vs 计划时间），不写回状态

#### 流程3：溯源查询

**流程描述 Process Description:**
用户以关键词召回计划/任务/注释并定位到所属计划。

**流程图 Process Flow:**

```
[输入关键词] → [系统检索索引] → [命中列表(计划/任务/注释)] → [点击命中项] → [定位到所属计划] → [结束]
```

**流程步骤说明 Step Details:**

| 步骤 Step | 操作者 Actor | 操作 Action | 输出 Output |
|----------|------------|-----------|-----------|
| 1 | 用户 | 输入关键词（可多词） | 检索条件 |
| 2 | 系统 | 索引检索（计划名/任务内容/注释内容） | 命中列表 |
| 3 | 用户 | 点击命中项 | 定位视图 |
| 4 | 系统 | 打开所属计划并高亮命中位置 | 溯源成功 |

**业务规则 Business Rules:**

- 检索范围 = 计划名 + 任务标题/内容 + 注释内容（v1.0 基础版）
- 命中项必须可回溯到所属计划（路径唯一）

### 6.2 跨系统集成 Integration Points

| 系统 System | 集成点 Integration Point | 集成方式 Integration Type |
|-----------|----------------------|----------------------|

## 7. 业务规则 Business Rules

### 7.1 核心业务规则 Core Business Rules

| 规则ID Rule ID | 规则描述 Rule Description | 规则类型 Rule Type | 例外情况 Exception |
|--------------|----------------------|------------------|------------------|
| R-001 | 计划=文件夹：一个计划对应一个文件夹，可嵌套（子计划） | 约束 | 根目录自身不属于任何计划 |
| R-002 | 内容单元=计划单片组件：仅 5 类（单选计划、多选计划、任务列表、任务详情、注释） | 约束 | v1.0 不开放自定义组件 |
| R-003 | 任务状态=三态机（未开始/进行中/完成） | 计算 | 展示层可显示"逾期"标记 |
| R-004 | 数据不出设备：应用无网络功能 | 约束 | 无（硬约束） |
| R-005 | 数据明文件 + 格式版本号：任何版本可读旧格式 | 约束 | 格式版本升级需迁移说明 |
| R-006 | 破坏性操作（删除/覆盖/移动）需二次确认 | 验证 | 应用内撤销（P1）前一律确认 |
| R-007 | 重名处理：同一父节点下重复文件名 → 提示冲突 | 验证 | 显示层提示；底层以物理路径唯一 |

### 7.2 业务规则详细说明 Detailed Business Rules

#### R-001: 计划=文件夹

**规则描述 Description:**
用户在计划库根目录下创建的每个文件夹是一个计划；计划树 = 文件夹树。

**适用范围 Scope:** 存储模块全流程。

**规则逻辑 Logic:**

```
IF 用户在根目录/计划内创建计划
THEN 物理创建一个文件夹（明文件结构，见 02 存储格式契约）
IF 计划包含子计划
THEN 子计划 = 子文件夹（嵌套不限层级，受文件系统路径长度限制）
```

**业务影响 Business Impact:** 决定"溯源"的路径模型（计划路径 = 文件夹路径）；决定数据可直接迁移/备份。

#### R-002: 内容单元=计划单片组件

**规则描述 Description:**
计划内容由 5 类组件表达，组件行为（渲染 + 组内编辑）是本项目差异化核心。

**适用范围 Scope:** 渲染模块。

**规则逻辑 Logic:**

```
IF 用户编辑计划内容
THEN 只能操作 5 类组件之一（单选计划/多选计划/任务列表/任务详情/注释）
ELSE 拒绝非组件内容（v1.0）
```

**业务影响 Business Impact:** 排版一致性（痛 P-001/P-005 的化解）；组件语义冻结是 01 阶段关键验收项。

#### R-003: 任务状态机

**规则描述 Description:**
任务状态仅三态，越级更新仅允许：未开始↔进行中↔完成（允许回退）。

**适用范围 Scope:** 任务列表/任务详情组件。

**规则逻辑 Logic:**

```
IF 任务状态 = 未开始 AND 用户点击开始
THEN 状态 = 进行中
IF 任务状态 = 进行中 AND 用户点击完成
THEN 状态 = 完成（记录完成时间）
IF 用户点击回退
THEN 回退至前一状态（保留时间线）
逾期 = 计划上的时间早于今天 AND 状态 != 完成（仅展示层计算）
```

**业务影响 Business Impact:** 任务闭环（痛 P-003）。
