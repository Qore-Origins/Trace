## 1. 架构概述 Architecture Overview

### 1.1 架构目标 Architecture Goals

| 目标维度 Goal Dimension | 目标描述 Target Description |
|---------------------|--------------------------|
| 业务目标 Business | 单用户自用桌面工具（非 SaaS）；MVP 三模块（存储/渲染/溯源查询）可用；远期可扩展 macOS/Linux 分发（同代码）与移动端（原生分轨，未排期） |
| 性能目标 Performance | 常规操作 < 1s；冷启动 < 3s；检索 ≤ 1s（≤1000 计划/≤10000 任务） |
| 可用性 Availability | 单机 100%（无网络依赖；无外部服务） |
| 可扩展性 Scalability | 数据规模上限内可扩展；格式版本化支持跨年演进；多端分发仅换壳（Electron 同代码打包） |
| 安全性 Security | 数据不出设备（无网络功能硬约束）；IPC 边界最小化；日志脱敏 |

### 1.2 架构视图 Architecture Views

| 视图类型 View Type | 说明 Description |
|-----------------|---------------|
| 逻辑架构视图 Logical View | 渲染进程 + 主进程服务 + 文件系统/索引/配置/日志（§3） |
| 部署架构视图 Deployment View | 单机部署（安装包 + 应用目录 + 数据目录 + 配置），无服务器（§4） |
| 数据架构视图 Data View | 明文件 JSON + 原子写 + 内存索引；数据流（§5） |
| 安全架构视图 Security View | IPC 隔离、路径防护、无网络、日志脱敏（§6） |

## 2. 架构原则 Architecture Principles

### 2.1 核心设计原则 Core Design Principles

| 原则 Principle | 说明 Description | 应用示例 Example |
|--------------|---------------|--------------|
| 分层原则 Layered | 渲染层/主进程服务层/文件数据层 明确分层 | 组件渲染只调 IPC 白名单 API |
| 单一职责 SRP | 每个模块专注一个职责 | 存储服务只做文件树与内容的读写 |
| 开闭原则 OCP | 组件类型可扩展不改渲染引擎 | 5 类组件由 type 分发渲染 |
| 依赖倒置 DIP | 主进程服务经接口暴露 | 存储/检索/配置服务接口化 |
| 接口隔离 ISP | IPC API 最小化 | 白名单方法按模块分组，不暴露原始 fs 能力 |
| **本地优先 Local-first** | 所有数据与状态本地，任何操作无网络依赖 | 应用无网络代码（审计项） |
| **明文件 Plain Files** | 数据=用户可见文件夹，可整库备份/迁移/第三方读 | 计划=文件夹 + JSON；备份=拷贝 |
| **渲染即编辑 WYSIWYG** | 组件渲染态与编辑态一体 | 点击即编辑，无模式切换（痛点约束） |
| **原子写 Atomic Write** | 内容落盘绝不半写 | 临时文件 + rename；崩溃不损坏 |

## 3. 逻辑架构 Logical Architecture

### 3.1 分层架构 Layered Architecture

#### 表现层 Presentation Layer（渲染进程）

| 组件 Component | 职责 Responsibility | 技术选型 Technology |
|--------------|-------------------|-------------------|
| 计划树视图 | 计划层级展示、导航、右键菜单、拖拽交互 | React + antd Tree（dnd: dnd-kit/内建拖拽） |
| 组件渲染区 | 5 类计划单片组件的渲染 + 组件内编辑 | React（受控组件，type 分发） |
| 溯源查询视图 | 搜索框、命中分段列表、回溯定位 | React + Zustand |
| 全局状态 | 树/当前计划/检索态/保存态 | Zustand |
| 状态栏 | 索引/保存/根目录状态 | React |

#### 服务层 Service Layer（主进程）

> 本项目无网关层/无微服务——主进程即"后端"，服务为进程内模块。

| 服务 Service | 职责 Responsibility | 技术 Type |
|-----------|-------------------|----------|
| StorageService | 计划树枚举、文件夹 CRUD、组件内容读写、原子写、移动/排序、破坏性操作校验 | fs/promises |
| SearchService | 索引构建（启动全量 + 变更增量）、关键词检索、命中路径映射、回溯定位 | FlexSearch（候选）+ 索引持久化 |
| ConfigService | 根目录持久化、窗口状态、格式版本号 | JSON（用户数据目录） |
| WatchService | 计划库外部变更监视（chokidar）→ 变更事件驱动索引增量 & UI 刷新 | chokidar |
| LogService | 本地日志（脱敏，不含计划正文） | 自研轻量 |

#### 数据层 Data Layer

| 组件 Component | 职责 Responsibility |
|--------------|-------------------|
| 计划库根目录 | 明文件数据（存储格式契约，见 5.1；详细契约=接口设计文档/DB 设计说明书） |
| 索引持久化 | 索引缓存文件（可重建；损坏仅重建，不损数据） |
| 应用配置 | %APPDATA%\trace\（根目录路径、格式版本、窗口状态） |
| 日志文件 | logs\（脱敏） |

### 3.2 服务拆分 Service Decomposition

```
溯源应用 Trace App
    │
    ├── 渲染进程 Renderer Process
    │       ├── 计划树 View (antd Tree)

    │       ├── 溯源查询 View
    │       └── 主界面壳/首次引导/状态栏
    │
    ├── 主进程 Main Process
    │       ├── StorageService（树/内容/原子写）
    │       ├── SearchService（索引/检索/回溯）
    │       ├── ConfigService（配置/根目录）
    │       ├── WatchService（外部变更监视）
    │       └── LogService（脱敏日志）
    │
    └── 数据 Data（本地文件系统）
            ├── 计划库根目录（明文件：计划文件夹树 + 内容文件 + 元数据）
            ├── %APPDATA%\trace\（配置 + 索引缓存）
```

### 3.3 核心业务流程 Core Business Flows

#### 计划创建与组织流程

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 树内新建  │──▶│ 校验命名 │──▶│ 物理建夹 │──▶│ 树刷新   │
│ 内联命名  │   │ 合法/同层│   │ 原子创建 │   │ 索引增量 │
└─────────┘   └─────────┘   └─────────┘   └─────────┘
```

#### 溯源查询（检索→回溯）流程

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 输入关键词│──▶│ Search   │──▶│ 命中列表 │──▶│ 回溯定位 │──▶│ 高亮展示 │
│ (300ms) │   │ 内存索引 │   │ 分段展示 │   │ 树展开   │   │ 2s 渐隐 │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
```

#### 原子写（所有持久化统一路径）

```
编辑内容 → 写临时文件（同目录 .tmp） → fsync → rename（原子替换） → 事件：索引增量
```

```
│  │ （原子写）     │  │ （全文检索+映射）│  │ （JSON 配置） │   │
```

> 存储格式契约（目录布局、内容文件、元数据、版本号）的完整定义 = 02「数据库设计说明书 DB Design」「接口设计文档 API Design」交付；本节约束其上位原则（明文件/原子写/版本号/路径即 ID）。

### 5.2 数据流转 Data Flow

**写数据流程 Write Flow（所有写操作统一）：**

```
用户操作（渲染进程）
    │ IPC 白名单
    ▼
[校验] 参数/路径（根目录内 prefix 校验、名称合法性、状态机）
    │
    ▼
[业务处理] StorageService
    │
    ├──▶ [原子写] 临时文件 → fsync → rename
    │
    └──▶ [索引增量] 变更事件 → SearchService 增量更新（异步）
    │
    ▼
[返回] 校验结果/新状态 → UI 刷新 + 状态栏"已保存"
```

**读数据流程 Read Flow：**

```
用户操作
    │
    ▼
[内存缓存] 进程内（树枚举/内容/索引）
    │
    ├── 命中 Hit ──▶ Return（毫秒级）
    │
    └── 未命中 Miss（首启/懒加载）
         │
         ▼
    [文件系统读取]
         │
         ├──▶ [写入缓存]
         │
         └──▶ Return
```

### 5.3 数据一致性 Data Consistency

| 策略 Strategy | 应用场景 Scenario | 实现方式 Implementation |
|-------------|----------------|----------------------|
| 强一致性 Strong Consistency | 计划/组件/任务内容本身 | 原子写（临时文件+rename）：进程崩溃或断电后，文件要么旧要么新，绝无半写 |
| 最终一致性 Eventual Consistency | 检索索引 vs 实际文件 | 变更事件 → 异步增量（≤1s 内追上，M5 验收）；外部文件变更由 WatchService 触发重建 |
| 冲突处理 Conflict | 外部工具同时修改计划库文件 | chokidar 检测 → 冲突提示 + 重载选项；应用内写入基于文件快照校验（修改时间冲突提示） |

### 6.2 安全措施 Security Measures

| 安全领域 Security Area | 措施 Measures |
|---------------------|--------------|
| 网络安全 | 无网络（硬约束）；依赖清单定期审计（NMP/Electron 已知漏洞） |
| 认证安全 | 无账号体系（不适用）；不做任何远端认证 |
| 授权安全 | 单用户（不适用）；系统文件权限处理：只读目录时降级提示 |
| 数据安全 | 数据不出设备；明文件即加密面（本地文件系统权限）；日志脱敏 |
| 应用安全 | IPC 白名单最小暴露；路径校验（resolve 后前缀在根目录内，防路径穿越）；组件渲染=受控纯文本（禁 dangerouslySetInnerHTML）；任务/名称长度与非法字符验证 |
| 运维安全 | 破坏性操作二次确认；原子写防半写；文档化备份指引 |

## 7. 性能架构 Performance Architecture

### 7.1 性能优化策略 Performance Optimization

| 层面 Layer | 优化策略 Optimization Strategy |
|----------|---------------------------|
| 前端（渲染器） | 计划树按需懒加载（折叠节点不读子内容）；组件渲染区局部刷新；列表虚拟化（任务列表量大时，M5 视实测） |
| 主进程 | 进程内缓存（树枚举/内容/索引）；变更事件驱动增量而非全量重建 |
| 数据 | 索引：启动全量构建（≤1s 规模）+ 变更增量；搜索=内存态（无磁盘 IO）；原子写仅落变更文件 |
| 打包 | 安装包 NSIS；应用启动不做初始化时网络/版本检查（保持冷启动冷路径最简） |

### 7.2 多级缓存 Multi-Level Cache

```
┌─────────────────────────────────────────────────────────────┐
│            UI 态缓存（渲染器：Zustand 内存 state）             │
└─────────────────────────────────────────────────────────────┘
                    │ Miss（懒加载加载子树/首击读入）
                    ▼
┌─────────────────────────────────────────────────────────────┐
│          数据缓存（主进程：内存对象 + 索引）                    │
│      树枚举缓存 · 内容对象缓存 · 检索索引（内存态）             │
└─────────────────────────────────────────────────────────────┘
                    │ Miss
                    ▼
┌─────────────────────────────────────────────────────────────┐
│          文件系统（计划库根目录：明文件 JSON）                  │
│  （WatchService 检测外部变更 → 缓存失效 → 重读）                │
└─────────────────────────────────────────────────────────────┘
```

> 无 CDN/分布式缓存（本地单机，不适用）。容量目标：1000 计划/10000 任务的全量内存对象 < 100MB（M5 实测校准）。

## 8. 可靠性架构 Reliability Architecture

### 8.1 高可用设计 High Availability Design

**不适用**（单机应用无多实例/主备场景）。对应替代指标：单机可靠运行——无网络依赖（断网照常）、重启秒恢复（RAM 数据即时重建，不等待外部服务）。

### 8.2 容错设计 Fault Tolerance

| 策略 Strategy | 说明 Description |
|------------|---------------|
| 超时重试 Retry | IO 失败（临时占用/抖动）→ 自动重试 1 次 + 用户可见重试按钮 |
| 熔断器 Circuit Breaker | 不适用（无外部调用链）；等价物=批量操作中断保护（如索引构建失败 → 降级为"检索不可用提示"，数据不受影响） |
| 限流 Rate Limit | 不适用 |
| 降级 Fallback | 未知/损坏组件 → 降级占位块渲染；索引损坏 → 重建（不损数据）；检索失败 → 提示并退化为"目录浏览" |
| 隔离 Isolation | 进程隔离（渲染器崩溃不影响主进程数据完整性）；单组件渲染异常不拖垮整页（React Error Boundary） |

### 8.3 容灾设计 Disaster Recovery

| 方案 Scenario | RTO | RPO | 策略 Strategy |
|-------------|-----|-----|-------------|
| 应用损坏/升级失败 | 分钟级 | 无数据损失 | 重装安装包；用户数据独立于应用目录，不受影响 |
| 计划库误删/损坏 | 手动 | 取决于用户备份 | 明文件整库拷贝 = 备份（引导文档化）；原子写保证非崩溃场景无半写；错误操作有二次确认 |
| 磁盘故障 | 按用户 | 按用户 | 数据可整体拷走（明文件），无锁定（格式契约公开） |
