## 1. 设计主题：迹 · Trace Mark

### 1.1 主题陈述

> **计划不是清单，是走过的迹。**

溯源 Trace 的一切界面，都是这句话的物化。应用的名字（溯源）、logo（起点圆点 + 台阶路径 + 回环）、组织口号（叩问本心，不忘初心）指向同一个意象：**从源头出发、留下轨迹、随时回到起点**。前端设计主题「迹」即从此生长，分三个子隐喻，各自驱动一组界面决策：

| 子隐喻 | 一句话 | 驱动的界面 |
|--------|--------|-----------|
| **计划是路径** | 计划不是待办表格，是一条从起点延伸的路 | 计划树有可见连接线；面包屑是"你走到了哪"；空计划 = 待画的纸 |
| **任务是足迹** | 任务不是勾选框状态，是"未出发/在途/抵达" | 三态视觉（见 §3.2）；完成的划线是"走过的桥"而非"删除" |
| **溯源是回望** | 搜索不是查列表，是"沿迹回望、找到源头" | 命中高亮沿路径点亮；2s 渐隐 = 看一眼源头、继续赶路 |

### 1.2 主题如何约束视觉（自检清单）

任何新界面的设计评审，问四个问题：

1. **迹在哪**：这个界面里"路径/进度"是否可见？（树连接线、进度划线、面包屑）
2. **源头在哪**：用户能否随时知道"自己在哪个计划里、它从哪来"？（面包屑 + 树选中态常亮）
3. **纸感是否干净**：内容区是否保持了"纸面"的克制（无装饰性噪音，见 §2.3）？
4. **动效是否服务回望**：动画只用于"定位/反馈"，禁止纯装饰动画。

### 1.3 与既有规范的衔接

| 项 | 取值 | 来源 |
|----|------|------|
| 主色（迹线蓝） | #1677FF → #0958D9 渐变（仅迹线/主按钮用渐变） | UI 规范 §2.1 |
| 源头点（Logo 圆点同色） | #1D39C4（深蓝，仅用于根节点/源头标记） | 应用图标 |
| 纸面 | #FFFFFF 内容 + #FAFAFA 布局底 | UI 规范 §2.3 |
| 字体/间距/圆角 | antd token，不另立 | UI 规范 §3/§4 |

## 2. 信息架构与视图设计

### 2.1 视图划分（渲染器只有三个顶层视图）

```
App
├── OnboardingView        首启引导（根目录配置）——条件渲染
├── WorkspaceView         工作台（常态唯一视图）
│   ├── TopBar            顶栏：品牌 / 全局搜索 / 新建计划
│   ├── PlanTreePanel     左：计划树（280px，可折叠为抽屉）
│   ├── ContentArea       右：当前计划（面包屑 + 组件序列 + 空态）
│   └── StatusBar         底：索引 / 保存 / 根目录
└── SearchOverlay         溯源浮层（叠在 WorkspaceView 上，非路由）
```

**为什么无路由**：单窗口工作台，"视图"由数据状态（有无根目录、有无选中计划）推导而非 URL。切换根目录 = 引导页条件重现。

### 2.2 WorkspaceView 布局网格

```
┌────────────────────────── 48px 顶栏 ──────────────────────────┐
│ [ logos dot ] 溯源 Trace   [ 搜索：沿迹回望… ]      [ + 计划 ] │
├────────── 280px ──────────┬──────────────────────────────────┤
│ 计划树（连接线可见）        │ 面包屑：● 源头 > 学期 > 周计划      │
│  ● 源头（根）              │ ┌────────── 12px 组件卡片序列 ───┐ │
│  ├─ ▸ 2026-A 学期          │ │ 单选计划卡                     │ │
│  │  └─ ▸ Web 全栈实训      │ ├──────────────────────────────┤ │
│  └─ ▸ Trace 开发计划       │ │ 任务列表卡（足迹三态）          │ │
│                          │ ├──────────────────────────────┤ │
│  [ + 子计划 ]（选中时浮现） │ │ 注释卡（旁批）                 │ │
├────────────────────────── 28px 状态栏 ─────────────────────────┤
│ ● 索引就绪    ✓ 已保存 10:32    根目录 D:\Plans\Trace           │
└──────────────────────────────────────────────────────────────┘
```

### 2.3 纸感（Content Area 克制原则）

- 组件卡片：白底、8px 圆角、极轻阴影；**卡片间 12px，无分隔线**——卡片序列如同"纸上排开的段落"。
- 禁止：卡片标题栏色条、彩色左边框、渐变卡片（渐变仅属迹线元素）。
- 一个计划一屏内可滚动浏览全貌——"计划有迹可循"的最小承诺。

## 3. 组件设计（理念 → 形态 → 交互）

### 3.1 计划树 PlanTreePanel

**理念**：树的连接线不是装饰，是"迹的骨架"——默认显示（antd Tree `showLine`），让"层级=路径"肉眼可见。根节点显示为**源头圆点**（logo 同款 #1D39C4 实心点），整棵树的"从源头生长"一目了然。

**形态**：
- 节点：folder 图标 + 名称（14px/500）；选中 = 迹线蓝底（Primary BG #E6F4FF）+ 左侧 3px 蓝条（"你在这条迹上"）。
- 悬停浮现两个文字按钮：`+子计划` `…`（重命名/删除收进 dropdown）——**常驻图标是噪音**，树需要安静。
- 拖拽：插入线即"迹的改道"；循环嵌套时插入线变红 + 提示（U 规范 §5.4）。

**交互**：懒加载（展开才取 children，`storage:treeGetChildren`）；右键菜单与悬停按钮等价（双通道，键盘用户友好）。

### 3.2 任务三态（足迹语义）——本应用最核心的组件视觉

**理念**：把"状态"翻译成"行程"。**勾选框保持 antd 单色蓝**，完成感交给**删除线 + 降色**——为什么？绿色勾选 = "对/错"的语义噪音，而划线是中性的"此路已走过"，与主题同构且避免双色混淆（UI 规范 §5.4 定稿的深层理由）。

| 状态 | 视觉 | 行程隐喻 |
|------|------|---------|
| 未开始 not_started | 空心圆环（12px 描边圈） | 未出发 |
| 进行中 in_progress | 实心蓝点（迹线蓝）+ 文字 Primary 色 | 在途（唯一带色的活跃态） |
| 完成 done | 圆环变 ✓（灰）+ 标题删除线 + 整行 45% 透明度 | 已抵达（迹留痕但不喧哗） |
| 逾期（展示层） | 行尾 Warning 橙 Tag「逾期」 | 计划的到达时间已过 |

**为什么进行中用色而完成不用**：同一时刻只能专注一条迹——"在途"是唯一值得吸睛的状态；完成的任务退场成背景（45% 透明），让未完成的自然浮到视觉前台。

**交互**：点击圆环循环切换三态（not_started→in_progress→done→in_progress…，与状态机一致）；`planned_at` 用日期输入即时改；行悬停浮现删除。

### 3.3 单选计划 SinglePlanCard

**理念**："本期唯一主线"值得一张**有重量的卡**。标题 16px/600（组件内最大字级），完成勾选放大（18px）——它声明的不是"一条任务"，而是"这一段路的终点"。

### 3.4 多选计划 MultiPlanCard

**理念**：并列可选项 = "岔路口"。选项行用 checkbox（复选语义），标题行右侧常显 `已选 x/n`（12px Text Tertiary）——岔路口的价值在"看清自己选了几个"，统计常显而非悬停。

### 3.5 注释 NoteCard（旁批）

**理念**：注释是读计划时写在**页边的旁批**。视觉：#FAFAFA 底 + 4px 左侧灰条 + 引号装饰（可选），字号 13px（比正文小半档）——刻意"退后一步"，与任务卡形成主次。**但内容参与检索**（溯源闭环），旁批不等于边角料。

### 3.6 溯源浮层 SearchOverlay

**理念**："回望"不该打断工作——浮层而非全页。输入即查（300ms 防抖），结果按 计划→任务→注释 分段；每项带**路径Breadcrumb**（源头在哪一望便知）。点击命中项 → 浮层收起 → 树路径自动展开 + 内容区滚动定位 + **命中卡片沿路径脉冲点亮 2s 渐隐**（渐变描边动画 = "沿迹点亮"）。

**为什么高亮要渐隐**：定位是"看一眼源头"的瞬间动作，常亮高亮会变成新的视觉噪音；2s 后回到纸感的安静。

### 3.7 首启引导 OnboardingView

**理念**：第一屏 = 品牌陈述 = 数据承诺。Logo 居中 + 口号「计划有迹可循」+ 一句话说明明文件存储（"数据以文件夹保存在你选的位置，可随时备份带走"）+ 单按钮。**没有注册、没有模板选择、没有网络**——空即是信任。

### 3.8 状态栏 StatusBar

**理念**：系统的"脉搏"低调常驻。三段：索引状态（●就绪/构建中 x%）、保存状态（✓已保存 hh:mm / 编辑中…）、根目录路径。保存状态是"渲染即编辑"唯一的安全感来源——用户没有保存按钮，状态栏必须替他确认。

## 4. 渲染器工程设计（Sprint 2 实现依据）

### 4.1 组件树与状态

```
App
├── ConfigProvider(zhCN)
└── AppView（按 appStore.phase 条件渲染）
    ├── OnboardingView
    └── WorkspaceView
        ├── TopBar          ← appStore / searchStore
        ├── PlanTreePanel   ← treeStore（nodes map / expandedKeys / selectedPath / dnd handlers）
        ├── ContentArea     ← planStore（currentPath / document / dirty / anchors）
        │   ├── Breadcrumb
        │   ├── ComponentRenderer（type 分发 → 5 类卡片 + FallbackBlock）
        │   └── EmptyState
        ├── StatusBar       ← appStore.indexState / planStore.saveState
        └── SearchOverlay   ← searchStore（open / keywords / hits / locating）
```

| Store | 状态（摘要） | 动作（摘要） |
|-------|------------|------------|
| appStore | phase: onboarding\|ready；rootDir；indexState | bootstrap() / setRootDir() |
| treeStore | childrenMap（懒加载缓存）；expandedKeys；selectedPath；loadChildren(p) / move(p, target, idx) / rename / remove / create |
| planStore | currentPath；document；saving；lastSavedAt；lastError；open(p) / saveDebounced() / mutateComponent() |
| searchStore | open；keywords；hits；query(kw) / locate(hit) |

### 4.2 关键交互时序

1. **渲染即编辑（防抖 + CAS）**：组件字段 onChange → 本地 document 即时更新（UI 零延迟）→ 500ms 防抖 `storage:savePlan(document, expected_updated_at)` → 成功：状态栏 ✓；失败 code 22：静默重拉最新文档 + message.warning("内容已在别处更新，已为你刷新")。
2. **外部变更（chokidar 事件）**：`trace:fs-external-change` → 若涉及当前打开计划 → 顶部 inline alert（不弹窗）"计划库在应用外被修改" + [重新加载]；树自动刷新。
3. **删除/切根**：Modal.confirm（危险红按钮）；文案必含"不可恢复"/"不迁移"。
4. **错误呈现策略**：字段级错误 → 内联红字；操作失败（IO/冲突）→ message；数据级异常（格式损坏）→ 卡片降级占位 + 状态栏记录。**禁止 alert/原生对话框**。

### 4.3 键盘与可达性

| 快捷键 | 动作 | 理念 |
|--------|------|------|
| Ctrl+F | 聚焦搜索 | 回望一步可达 |
| Ctrl+N | 新建计划 | 最高频动作 |
| F2 | 重命名选中计划 | 文件管理器肌肉记忆 |
| Delete | 删除选中（仍需 confirm） | 危险但可预期 |
| ESC | 关浮层/退出编辑（放弃未提交行） | 出口一致 |

`prefers-reduced-motion` 时全部动画 ≤50ms（UI 规范 §8.3）。

## 5. 视觉母题应用清单（主题落地的具体位置）

| 母题元素 | 用在哪 | 不用在哪 |
|---------|--------|---------|
| 渐变迹线（蓝→深蓝） | 选中节点左条、进行中圆点、回溯脉冲描边、主按钮 | 卡片边框、标题、背景 |
| 源头圆点 #1D39C4 | 树根节点、面包屑首项、logo 位 | 一般图标（避免满屏圆点） |
| 划线（strike） | 完成任务标题、已完成单选计划标题 | 注释、路径 |
| 纸面留白 | 内容区（组件序列 12px 间距、无分隔线） | 树（需要密度：8px） |
