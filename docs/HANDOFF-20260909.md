### F1（最重要）antd v5 静态方法在 React 19 下静默失效
- 现象：用户报「删除功能无效，点击删除后无效果」
- 根因：antd v5 的 `Modal.confirm` / `Modal.info` / `message.*` 静态方法内部用 `ReactDOM.render`，React 19 已移除 → 调用后静默不渲染（console 有 `[antd: compatible] antd v5 support React is 16 ~ 18` 警告）
- 修复：`src/renderer/src/main.tsx` 入口注入 `unstableSetRender`（antd 官方 v5-for-19 指引），用 `createRoot` + WeakMap 缓存 root 渲染
- **注意：这段代码是所有 antd 静态方法的命脉，任何时候不能删**
- 影响面：删除确认、切换目录确认、关于弹窗、全部 message 提示

### F2 删除不发 `trace:plan-changed` 事件 → 搜索索引幽灵条目
- `src/main/services/storage-service.ts` `deletePlan` 是所有结构变更中唯一不发事件的，搜索索引对已删计划残留条目
- 修复：删除成功后 `bus.emit('trace:plan-changed', { path: rel })`
- `test/storage-service.spec.ts` 补了事件断言用例

### F3 删除失败静默吞错
- 原先确认弹窗 `onOk` 用 `.catch(() => undefined)` 吞错，文件被占用/已被外部删除时用户毫无反馈
- 修复：`tree-store.ts` `removePlan` 补 try/catch + `message.error`；新增 i18n 键 `errors.deleteFailed`（中英）

### F4 删除后脏状态残留
- `expandedKeys` / `childrenMap` / `loaded` 不清理被删子树键 → 同名重建文件夹后意外自动展开、脏数据
- 修复：`removePlan` 内统一按 `k === path || k.startsWith(path + '/')` 过滤清理

### F5 删除已打开的计划 → 误报「目标位置不存在」
- 竞态链：`deletePlan` 成功 → 发 `plan-changed(被删路径)` → plan-store 订阅以为是外部修改 → 静默重拉 `open(已删路径)` → `readPlan` 报 PATH_NOT_FOUND 弹窗，但文件其实删成功了
- 修复（三处）：
  - `tree-store.ts` `removePlan`：发删除 IPC **前**先 `close()` 被删子树内打开的计划
  - `plan-store.ts` `flush`：IPC 往返后 re-check `currentPath` 快照，目标已换/已关则静默丢弃
  - `plan-store.ts` `close`：清 `pendingMutate` 防保存重排

## 六、本会话沉淀的避坑经验

- **antd v5 + React 19**：一切 `Modal.xxx` / `message.xxx` 静态调用都依赖 main.tsx 的 `unstableSetRender` 注入（见 F1），别动那段
- **CDP 调试法**（本项目验证 UI 的标准手段）：
  - `npx electron-vite dev -- --remote-debugging-port=9222` 启动（后台跑）
  - Node 脚本连 `http://127.0.0.1:9222/json/list` 取 page 的 webSocketDebuggerUrl，用 `Input.dispatchMouseEvent`（带坐标）做真实点击；`Runtime.evaluate` 查状态
  - **坑**：Electron 单实例锁 + vite 端口残留 → 启动前先 `Get-Process electron | Stop-Process -Force` 清场，否则 CDP 端口连不上（表现为 ECONNREFUSED 但进程在）
  - **坑**：合成 `MouseEvent('mouseover')` 不触发 antd Dropdown hover；测 hover 态用 `CSS.forcePseudoState`（需先 `DOM.getDocument` + `CSS.enable`）
  - **坑**：发牌动画（320ms + stagger）进行中 DOM 坐标会过期，几何断言前等动画落定
- **DEV 探针**：`window.__tree` = useTreeStore（main.tsx 尾部仅 DEV 注入），可直接 `setExpanded` / `select` 驱动状态
- **树状态铁律**（BR-003 全历史教训）：任何 +号/展开键状态变更必须主动刷新，NEVER 依赖重启
- **协作铁律**（用户原话级要求）：
  - 每阶段结束讲清三件事：下一步干嘛 / 等什么 / 还差什么
  - 阶段完成可提前开下一阶段，不干等用户指令
  - 用户 AI 额度有限——长任务拆批，别赌单次会话
  - UI 改动必须自测遮挡/越界（用户会拿真机截图级反馈）
  - npm 用 npmmirror 源；网络问题先确认用户 VPN 状态
