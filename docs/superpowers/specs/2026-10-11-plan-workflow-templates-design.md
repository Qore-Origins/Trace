# 按个人目录习惯创建计划的工作流设计

> 状态：设计已获用户确认，待按[分阶段实施计划](../plans/2026-10-11-plan-workflow-presets-implementation.md)开发。2026-10-11。本文定义目标行为，不表示功能已经实现。

## 1. 问题与依据

用户希望 Trace 和小沅按照自己的目录与命名习惯做事：先决定计划放在哪个文件夹，再依据该文件夹和计划目标日期命名，生成合适的组件与内容；需要时一次创建互相关联的多份计划。`{this.folder_name}_{date}_{title}` 是其中一种命名表达式，`this.folder_name` 是计划将放入的**直接父文件夹**名称，`date` 是计划目标日期。

只读检查 `D:\Desktop\Plan` 发现：顶层有 `Daily_Plan`、`Weekly_Plan`、`Future_Plan`、`Feature_Plan`、`Short-Term_Plan`、`Medium-Term_Plan`、`Long-Term_Plan`、`Diary`、`Prompt` 和 `今日任务`；`Feature_Plan/Qore/Trace` 等项目目录是多级结构。现有文件名同时使用日期、日期范围、标题和两位序号，分隔符也不完全一致。不能从少量旧文件推定用户以后必须采用某一种统一格式。

当前命名模板仅按准确父路径匹配，变量只有 `{date}` 和必填 `{title}`，日期取实际创建日；`plan.create` 只创建一份计划，最多带一个初始任务列表。现有计划引用能连接计划或组件，但不是整套周日工作流。新设计必须保留旧规则与旧计划，避免直接操作真实计划库。

## 2. 方案取舍

| 方案 | 内容 | 取舍 |
|---|---|---|
| A：只扩充命名变量 | 在现有模板中增加父文件夹名、目标日期等变量 | 改动小，但放置位置、内容和多计划关联仍靠手工操作 |
| **B：可配置工作流预设** | 一个预设组合目标目录、命名规则、内容模板及创建数量；同一解析器服务于 UI 和小沅 | **用户已选择**。覆盖实际需求，规则可预览、可复用，并保留单计划入口 |
| C：开放脚本式模板 | 用户编写任意表达式、循环或文件操作 | 灵活但难以预览和约束，不适合作为本地计划库的默认写入能力 |

设计分为四个可独立理解的部分：**目标目录规则 → 名称模板 → 内容模板 → 创建流程**。预设把四者连接起来；修改某一种命名格式不应迫使用户重做组件排版。

## 3. 计划放置与规则作用域

1. 从文件树某目录点“新建计划”时，自动匹配该目录的默认工作流预设，直接显示**可修改的预览**，不先要求逐次挑选预设。用户仍可在预览中切换预设、目标目录和适用的日期、标题、内容。预设可指定已有目标目录，也可使用“当前选中的目录”；预览始终显示相对库根的完整目标路径，例如 `Feature_Plan/Qore/Trace`。小沅不能仅凭 `Trace` 这个末段名称猜测目的地。
2. 目标目录必须已存在且经过主进程路径安全检查。将来若允许创建缺失的项目目录，新增目录须列在同一预览中，不得暗中补建。
3. 预设的自动匹配顺序为：当前目录显式默认预设 → 已启用且适用于后代的分类默认预设 → 已启用的全库默认预设。每个作用域只允许一个默认预设；若配置或迁移后同级仍有多个候选，显示候选列表而不暗中挑选。无匹配预设时走现有单计划新建入口。分类和全库匹配都须由用户显式开启；准确父路径的现有名称规则不因此自动继承。
4. 预设显式设置名称模板时使用该模板；预设若设置为“沿用目标目录命名规则”，则按准确父路径自定义规则 → 用户启用的分类规则 → 用户启用的全库规则 → 未停用的内置规则 → 手填完整名称解析。手动切换预设只影响本次创建，除非用户另外保存为该目录默认。预览必须显示命中的规则来源。
5. `Diary` 自动创建仍遵循现有 `Diary/YYYY-MM-DD` 约定，不被通用计划命名规则覆盖。`今日任务` 的既有文件保持原样；将来若做今日视图，从日计划读取任务，不复制一套状态。

## 4. 名称模板语义

模板只能使用下表白名单变量和普通文件名文字，不支持脚本、条件、路径分隔符或隐式改写。变量可以按任意顺序组合，生成完整计划**目录名**；目录内仍是 `plan.json`。

| 变量 | 含义 | 示例上下文下的值 |
|---|---|---|
| `{this.folder_name}` | 目标目录的直接父文件夹名；目标为库根时取库根目录名 | 放入 `Feature_Plan/Qore/Trace` 时为 `Trace` |
| `{category_name}` | 库根下第一级目录名；目标为库根时取库根目录名 | `Feature_Plan` |
| `{title}` | 创建时输入的标题；模板不用它时标题输入可选 | `迭代计划` |
| `{date}` | 单日计划的**目标日期**，本地日历 `YYYYMMDD` | `20261012` |
| `{date_iso}` | 同一目标日期，`YYYY-MM-DD` | `2026-10-12` |
| `{year}`、`{month}`、`{day}` | 单日目标日期的本地年月日；月、日补零 | `2026`、`10`、`12` |
| `{week_start}`、`{week_end}` | 周期工作流起止日，`YYYYMMDD`，均包含在周期内 | `20261012`、`20261018` |
| `{created_date}` | 实际创建日，`YYYYMMDD`；用于确实需要按创建日归档的模板 | `20261011` |
| `{sequence}` | 同一目标父目录与模板上下文中的下一个可用两位序号 | `01` |

- `{date}` 在周期预设中不自动猜作起始日或结束日。周期名称应使用 `{week_start}` 和 `{week_end}`；若模板需要 `{date}`，创建界面须明确取得独立的单日目标日期。
- `{sequence}` 在预览时给出候选号；提交时重新核对同目录的实际文件名。重名不自动追加未知后缀，而是重新预览或让用户改名。超过两位时自然扩展为三位。
- 旧版模板中的 `{date}` 在新流程启用后由可见的“目标日期”字段提供。打开时可预填当天，但必须显示日期与最终名称；小沅在目标日期无法从用户请求或已选上下文确定时应询问，不擅用请求发送日。
- 缺少 `{title}` 的模板可以保存，例如周计划的日期范围命名；最终名称仍必须通过现有文件名、长度、保留名及同名校验。任一必需变量缺失时不能提交。

建议提供可选模板样例，不批量覆盖现有规则：

| 使用场景 | 模板 | 可能结果 |
|---|---|---|
| 当前文件夹通用计划 | `{this.folder_name}_{date}_{title}` | `Trace_20261012_迭代计划` |
| 顶层分类计划 | `{category_name}-{date}-{title}` | `Future_Plan-20261012-长期研究` |
| 同日多份项目计划 | `{this.folder_name}-{date}-{sequence}` | `Trace-20261012-01` |
| 周计划 | `{this.folder_name}_{week_start}-{week_end}` | `Weekly_Plan_20261012-20261018` |
| 日计划 | `{this.folder_name}_{date}` | `Daily_Plan_20261012` |
| 按创建日归档 | `{this.folder_name}_{created_date}_{title}` | `Trace_20261011_会议整理` |

## 5. 工作流预设与内容模板

初始预设是可修改的建议值，不根据目录名强行重排旧文件。

| 预设 | 目标目录 | 数量与名称 | 初始组件顺序 |
|---|---|---|---|
| 当前文件夹计划 | 当前选中目录 | 1；用户选择该目录适用名称规则 | 标题、目标说明、任务列表、记录；可选空白模板 |
| 项目或功能计划 | 用户选定的项目目录，如 `Feature_Plan/Qore/Trace` | 1；可用 `this.folder_name` 和 `sequence` | 标题、背景与目标、阶段任务、完成标准、过程记录 |
| 未来计划 | `Future_Plan` 或用户指定目录 | 1；目标日期加标题 | 标题、目标、下一步任务、补充记录 |
| 周与日联动 | `Weekly_Plan` 加 `Daily_Plan` | 1 份周计划，最多 7 份新日计划；已有同日日计划复用 | 见下一节 |

内容模板保存**组件类型、顺序、初始标题和可编辑提示文字**。支持从已有组件中选择 `heading`、`note`、`task_list` 与 `plan_reference`；`mood` 仅显式加入，避免与 `Diary` 重复。组件模板只是创建时的初稿，生成后用户照常编辑，不在以后重套模板覆盖内容。每个预设可关联自己的内容模板，目录命名规则也可独立修改。

### 5.1 预设怎样配置

“设置 → 工作流预设”提供新建、复制、编辑、停用和删除。每份预设明确保存：名称、适用目录范围、是否为该范围默认、创建时的目标目录规则，以及一组有顺序的**生成项**。每个生成项分别指定目标目录、名称模板、内容模板和生成次数规则。`{this.folder_name}` 对每个生成项的**最终目标目录**分别求值，而不是固定取触发工作流的目录。

首版生成次数规则仅有“生成一次”和“周期内逐日生成”；后者必须有明确起止日期，最多七天，不能成为任意循环或脚本。普通项目预设由一项“生成一次”组成；周与日预设由“在 `Weekly_Plan` 生成一次周计划”和“在 `Daily_Plan` 对七个目标日逐日生成”两项组成。将来增加另一类批量计划时复用生成项模型，而不复制周计划专用代码。生成项之间可声明稳定 ID 引用，必须在全批预览中解析并检查。

保存预设前用示例目录、标题、目标日期和可选周期展示全部输出路径与组件顺序。保存后仅影响后续创建；编辑预设不重命名旧计划、不重新生成旧组件。删除正在作为目录默认值的预设时，必须同时清除该默认绑定并让该目录回退到下一条明确适用的规则。

## 6. 周与日联动流程

1. 在当前周未结束时可启动“规划下一周”。默认起日为上一份已识别周计划结束的次日；用户可改起日，系统据此算连续 7 天，并提示与已有周范围的重叠。既有样本是周四至周三，不能强制解释为周一至周日。
2. 先写周目标，再列候选执行任务；把每个任务分配到七天之一，或暂留“待分配”。任务在创建时只落入对应**日计划**一次，`planned_at` 与日计划目标日期一致。周目标与日执行任务是不同粒度，不在周计划复制同名执行任务。
3. 一周最多创建一个周计划和七个日计划，即最多八个 `plan.json`。默认七天各有一份日计划；没有任务的日子是留白或休息日，不虚构任务。目标日若已有已确认的日计划，预览中显示“复用（并单独确认任务合并）或取消”；不得生成第二份同日期计划或覆盖现有内容。实际新建数因此可能小于八。
4. 周计划布局依次为日期范围与草稿状态、本周目标、七天简明分配、待分配事项、交接区、周末复盘。七天摘要逐行显示日期、任务数、完成数及进入日计划的入口，详情按需展开。
5. 日计划布局依次为日期与当天重点、唯一的执行任务列表、过程记录、收尾复盘。多项目任务可在分配界面按项目筛选；日计划内保持统一执行列表，避免同一天拆成多个状态源。
6. 周计划以稳定计划 ID 关联每日计划，并从每日任务计算进度；日计划是任务状态真源。生成时为关联目标分配稳定 ID。移动或重命名文件后，关系仍按 ID 查找；路径只作显示快照。
7. 先创建的下一周为草稿。当前周未完成任务先列为“待交接”引用，不提前复制；交接时逐项选择留在原周、移至下周某日或不再安排。若生成新日任务，保存来源标识，并将旧项标为已转移或等价的明确状态。现有三态模型尚无该状态，实施时须补齐，不得把旧项标为完成。

## 7. 创建界面、小沅与写入边界

- 文件树“新建计划”按第 3 节自动匹配预设后立即展示可修改预览，列出预设名称、目标目录、目标日期或区间、标题、命名规则来源、组件顺序和最终路径；预览中可切换“当前文件夹计划、项目计划、未来计划、周与日联动”等预设。独立工作流入口可先选预设。周流程另显示七天分配与文件清单。
- UI 与小沅使用同一套主进程解析器：输入预设、目标目录、日期、标题、任务分配，输出只读预览；提交时再次校验目录身份、名称冲突、计划修订和库身份。渲染进程不得直接写文件。
- 小沅可提出预设与候选内容，但不能靠提示词私下拼文件名、臆测项目目录或连续调用多次单计划创建来冒充一次工作流。批量写入展示逐文件路径和组件摘要，依现有确认策略由用户审阅后执行。
- 单文件沿用原子写。跨 `Weekly_Plan` 与 `Daily_Plan` 的八文件操作没有文件系统级整体原子性：实施时需记录操作批次和每个已创建目录的身份；中途失败只回收该批次确认属于自己的新目录，未能回收的逐项报告并支持安全续做。不得删除原有计划或声称失败后一定“零副作用”。
- 重新打开同一周期的预设，应定位已存在的周草稿并提供继续编辑，不能凭相同输入反复创建。目录同名、目标日期重复、旧计划格式损坏、切换计划库和外部文件改动都必须在提交前重新检查。

## 8. 数据与兼容边界

- 现有 `.trace/plan-name-templates.json`、准确父路径规则、用户明确停用的内置规则继续有效；新规则不得因为升级而让已停用默认值重现。新工作流配置保存在当前库 `.trace/plan-workflows.json`，并通过单一规则解析入口统一展示来源与优先级。旧计划目录和 `plan.json` 不批量重命名或改写。
- 新创建的关联计划需要机器可读的周期、目标日、草稿状态、稳定目标 ID 和任务来源信息。在计划文档中增加可选、经过验证的 `workflow` 元数据；旧版无该字段时按普通计划读取。不得只把关系写进自由文本，也不得只保存在会丢失导出语义的 UI 状态里。
- 对已有带日期的日计划，只能在预览阶段识别为候选匹配；名称中有日期不等于已确认相同计划。旧文件无明确目标日元数据时，由用户确认它是否就是目标日日计划；确认后只复用或取消，判定不是该日日计划时才可另建，不静默合并。
- 计划库配置随库移动；不同计划库有各自规则。所有变量值在主进程按白名单和文件名规则验证，任何外部输入均不得变成路径穿越或隐藏文件操作。

### 8.1 最小数据形状

设计中的规则解析输入为 `library_id`、已选择或由预设确定的 `parent_path`、`target_date` 或 `period`、`title`、`profile_id` 与必要的任务分配。输出预览包含每个目标相对路径、命中的规则来源、展开后的名称、组件草稿、计划间引用、已存在对象及冲突。提交只接受与本次预览及当前库身份匹配的输入；预览不是写入许可。

`.trace/plan-workflows.json` 的首版只保存三类可编辑配置：显式启用的分类／全库名称规则、按顺序排列的内容模板、引用这些规则和模板的工作流预设。准确父路径的旧规则继续由 `.trace/plan-name-templates.json` 保存；两份配置通过一个解析器合成，并在设置界面显示实际来源，不互相复制出第二份权威值。

新周计划的 `workflow` 元数据至少有 `kind: week`、`status: draft | active | closed`、`start_date`、`end_date`、按日期索引的 `day_plan_ids`；新日计划至少有 `kind: day` 与 `target_date`。跨周转移记录源 `plan_id` 和源 `task_id`；旧任务增加明确的已转移状态，且旧计划历史保持可读。这些结构均须由主进程校验，旧版无 `workflow` 的文档不自动补字段。

## 9. 可验收行为与实施边界

1. 在 `Feature_Plan/Qore/Trace` 用 `{this.folder_name}_{date}_{title}` 且目标日期为 2026-10-12，预览和落盘目录名均为 `Trace_20261012_迭代计划`；提前一天创建仍使用目标日期。
2. 在 `Weekly_Plan` 使用周期模板能生成起止日期；日计划按各自目标日命名。目标日期跨月、跨年和闰日时预览正确。
3. 准确父路径规则、显式分类规则、全库规则与内置规则各按第 3 节优先级命中；旧版自定义和禁用状态不被覆盖。
4. 在 `Feature_Plan/Qore/Trace` 点“新建计划”时自动匹配该目录默认预设并先展示可修改预览；有同级多候选时先显示候选列表；手动切换预设不永久改写目录默认。
5. 用户能复制、修改、停用预设并预览每个生成项；周输出的 `{this.folder_name}` 为 `Weekly_Plan`，日输出的同名变量为 `Daily_Plan`。
6. 同一目标日已有日计划、同名目录或路径不安全时不覆盖，明确显示冲突和处理选择。
7. 周任务只在日计划中改变状态，周视图读取汇总；下周可在本周结束前起草，未完成任务不会自动复制。
8. 小沅与手工创建的名称、目录和内容预览一致；批量写入失败时逐项说明已创建和待处理文件。
9. 旧计划和用户真实计划库在配置保存、预览及设计阶段均不被迁移或改写。

本规格只确定目标行为与边界。实施已拆成命名上下文与兼容层、内容模板、单计划预览、周日批次及小沅共用入口，详见[实施计划](../plans/2026-10-11-plan-workflow-presets-implementation.md)。设计阶段未修改源码、运行迁移或创建真实计划。
