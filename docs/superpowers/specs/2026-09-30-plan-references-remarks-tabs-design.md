# 跨计划引用、组件 Markdown 备注与计划标签栏设计

日期：2026-09-30

状态：设计各节已与用户确认；完整规格待用户评审。当前没有代码实现。

## 背景与现状

Trace 当前一次在右侧内容区打开一个计划。左侧树负责定位计划，计划文档以明文 `plan.json` 保存，`PlanDocument.components` 按顺序存放组件。组件有文档内唯一 ID，但计划本身没有稳定 ID。备注目前只能作为独立注释组件存在；计划文件夹改名、移动和删除由主进程存储服务执行。

用户选定从未来计划卡片中的前三项开始：跨计划关联/软链接、所有组件的 Markdown 备注，以及右侧内容区的多计划标签栏。三项互相协作：引用导航依赖标签切换，软链接依赖稳定的计划和组件身份，备注与引用展示都复用现有 Muya 实时 Markdown 体验。

## 目标

1. 允许用户从计划内跳转到其他计划或组件，并在需要时以内嵌只读方式查看唯一原件。
2. 任意组件均可附加 Markdown 备注；编辑器按需挂载，渲染态可读且不拖慢普通卡片。
3. 同时打开多个计划，提供明确的标签切换和关闭入口；重启及切换计划库后，各库的标签状态互相隔离。
4. 应用内重命名、删除与移动计划/组件时，关联保持可解释、可修复，不静默丢失。
5. 延续本地优先、明文文件可迁移、现有主题 token、IPC 边界和路径安全规则。

## 用户已确认的决策

- 计划内同时提供两种关系：普通关联，以及软链接式实时嵌入。
- 普通关联可指向计划或计划内组件；软链接只可指向普通原生组件，不以其他引用作为原件。
- 软链接处实时展示原件，但不在引用处编辑；“编辑原件”切换到来源计划并聚焦原组件。
- 计划 ID 按需分配：计划首次成为引用目标时才写入稳定身份，不批量迁移旧计划；组件沿用现有 ID。
- 删除或重命名会影响关联时，先提示用户并询问是否更新受影响的关联内容。删除时，对每条引用分别选择替代目标；用户也可以保留失效引用或取消操作。
- 任意组件可有 Markdown 备注，沿用现有注释的实时渲染体验；空备注显示“添加备注”，非空备注显示渲染态，进入编辑时才挂载 Muya。
- 标签栏只放在右侧编辑/内容区；同一计划只能有一个标签，从树中再次打开已存在的计划时切换其标签，不重复创建；标签按计划库保存并在下次打开时恢复，失效/已删除目标应跳过或修复。

## 方案比较与采用方案

### 计划关系

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 仅普通超链接 | 改动小、结构直观 | 不能在原计划旁查看目标组件，也无法跟随原件实时变化 | 不采用 |
| 仅复制目标内容 | 阅读方便 | 形成副本，容易过期并造成编辑来源不明 | 不采用 |
| 普通关联 + 只读软链接 | 跳转与就地查看各有清晰语义，编辑始终回到唯一原件 | 需要稳定身份、反向引用查询和变更提示 | 采用 |

### 标签布局

已用本地浏览器视觉稿比较“右侧内容区标签”与“覆盖整个工作区的标签”两种布局。用户选择右侧内容区标签；不再在顶部菜单附近增加第二组容易混淆的页面导航。

## 设计细节

### 1. 计划与组件引用

#### 引用组件与行为

- 插入组件菜单新增“计划引用”组件；创建时选择目标计划/组件和关系类型，并可修改显示名称。
- 普通关联保存目标身份和名称快照。引用卡片提供清晰的打开动作：目标为计划时打开该计划；目标为组件时打开来源计划并滚动/聚焦目标组件。
- 软链接必须指向普通原生组件。引用卡片以只读方式实时呈现其可视内容，不复制该组件的拖拽、删除、勾选或编辑控制；显示“编辑原件”动作，点击后激活来源计划并聚焦原件。
- 每个计划引用组件仍有自己的组件 ID。被引用的 `plan_reference` 不可再作为其他引用的目标，阻止软链接递归和循环嵌套。
- 普通关联与软链接均限定在当前计划库；不把外部文件路径或其他库当作可解析目标。

#### 稳定身份与索引

- `PlanDocument` 增加可选稳定 `plan_id`。仅当计划首次成为引用目标时分配，并随计划文件在 Trace 内重命名/移动而保留。
- 组件目标由 `(plan_id, component.id)` 标识；计划目标由 `plan_id` 标识。展示名称/路径只作快照，不充当身份。
- 引用组件的数据保存在引用来源计划的 `plan.json`。反向引用表是主进程可重建的派生索引，不取代明文计划文件作为事实源；保存、重命名、移动、导入和删除会使相关索引失效并刷新。
- `plan_reference` payload 至少包含关系模式（普通关联/软链接）、目标 `plan_id`、可选 `component_id` 与名称快照；软链接必须包含 `component_id`，普通关联可以只指向计划。
- 现有旧计划没有 `plan_id` 时按旧格式直接读取，不做全库迁移。用户创建首条关联时，仅为目标计划补写 ID。
- 导入计划子树时，包内计划原 ID 如与当前库冲突，导入过程为冲突计划重分配 ID，并重写包内指向这些计划的引用；指向包外目标的引用保留原目标 ID，若当前库无法解析则按失效引用呈现。导出仍随子树保存现有 ID 与引用数据。

#### 重命名、移动与删除

- 应用内重命名计划或被引用组件时，仅当存在入站引用才弹出影响说明。选择“更新关联”时同步引用中的名称/路径快照；选择“保留原显示”时只保留旧快照，底层稳定 ID 仍指向当前原件；取消则不执行重命名。
- 应用内移动计划不要求额外确认；稳定 ID 使关联继续指向原件，引用卡片可刷新当前路径。
- 删除计划时统计计划及其将一并删除的子树内、且来源计划会留存的入站引用；子树内随删除一并移除的引用不列为受影响项。删除组件时统计来源计划会留存且指向该组件的入站引用。只有存在受影响引用时才增加关联影响对话框。
- 删除确认选择“更新关联”后，为每条受影响引用分别选一个替代计划/组件；软链接只接受兼容的普通原生组件。用户可选择“保留失效引用”，使其留在原位置并显示目标已删除状态；“取消”不删除目标。
- 批量变更先校验所有目标与来源文档，再逐个使用现有原子写入路径。若写入失败，不继续删除目标；已成功更新的引用仍指向有效替代项。由于文件系统不提供跨多个 `plan.json` 的原子事务，错误提示须报告操作未完整完成且保留目标；重试时重读引用索引，只处理仍指向原目标的引用，因此已成功的更新不会被重复处理。
- 若计划在 Trace 外部被移动或删除，无法在操作前弹窗；监视器发现后将其标为失效，提供重新定位/替换入口，不崩溃或静默移除引用。

#### 失效与安全状态

- 目标计划不存在、目标组件已删除、文档损坏或路径越界时，引用呈现明确的失效占位和可用修复动作；不得渲染或读取计划库外的路径。
- 点击已失效的普通关联不导航；点击软链接的“编辑原件”不创建空计划、不伪造目标。
- 反向索引失效时通过主进程安全地重建；扫描范围只限当前库，所有文件操作遵守 `path-safety.ts`。

### 2. 组件 Markdown 备注

- 所有组件共有可选 `remark?: string` 字段，包括任务列表整体；首期不扩展为任务列表中每一条任务各自的备注，也不新建独立备注卡片。
- 空状态提供轻量“添加备注”入口；非空状态在组件主要内容之后展示已渲染的 Markdown。视觉上属于组件的次级信息，不与组件主标题、任务勾选等主操作争夺层级。
- 点击备注正文进入编辑态；备注中的链接仍执行链接行为，不因进入编辑交互而失去可点击性。编辑态复用现有 Muya 实时渲染和保存路径，可清空后移除备注字段。
- Muya 只在用户编辑该备注时挂载，保存或取消后退出编辑态；其他组件只渲染内容，不各自常驻一个编辑器。
- Markdown 能力与现有注释一致，链接和已支持的代码/图表渲染沿用同一安全策略；不另建 Markdown 语法或渲染内核。

### 3. 计划标签栏

- 标签栏位于右侧内容区顶部、计划画布之前，不改变顶栏的“计划 / 日记 / 回忆”页面导航，也不在左侧树中复制标签状态。
- 点击树中的计划：若已有标签则激活它；若没有则新建一个标签并打开计划。纯文件夹仍不产生计划标签。
- 每个计划库独立保存打开标签和当前活动标签；打开顺序保持稳定。关闭标签不会删除磁盘计划；关闭后选择相邻标签（优先左侧，否则右侧）；无标签时显示现有空内容状态。
- 标签标题跟随计划名称更新，标签关闭仅修改工作区状态。所有标签相关的 plan 读写仍走既有 IPC/CAS 保存路径。
- 标签状态保存在该库的 `.trace` 元数据中，包含库内相对路径、活动路径，以及目标计划本来就有 `plan_id` 时的可选身份；为标签恢复而不额外批量分配 ID，也不保存计划内容。应用内移动/重命名同步更新标签路径；恢复时逐个验证路径，身份可确认时尝试修复外部移动，否则跳过失效项并提示，不阻断工作区打开。
- 各库标签彼此隔离。切换计划库时加载新库标签；不把上一库的活动计划显示成新库的计划。
- 标签过多时仅在标签栏内滚动/收敛，不覆盖编辑区、顶栏或窗口控件；亮暗主题使用现有语义 token，并支持键盘焦点和 `prefers-reduced-motion`。

## 架构与数据流

1. Renderer 通过 IPC 请求打开、保存、列出引用影响和执行重命名/删除确认后的动作；不直接访问文件系统。
2. Main process 校验当前 library root、路径和引用目标，负责按需分配 `plan_id`、扫描/维护反向引用、构造删除/改名影响报告，以及执行原子单文件写入。
3. 引用组件的唯一数据源是其来源计划中的 `plan_reference` payload；预览通过目标 `(plan_id, component.id)` 读取实时组件，前端展示为只读内容。
4. 编辑引用原件时，工作区激活来源计划标签并将目标组件 ID 交给内容区聚焦；该操作不创建第二个组件实体。
5. 备注是公共 `Component` 上的可选 Markdown 数据，仍随原计划文档一起保存；标签列表/活动项是库级 UI 状态，独立于计划内容。
6. 现有 `format_version: '1'` 继续读取旧文档；新增身份、备注和引用均为可选扩展字段。新版本必须完整保留这些字段；旧版本对新的引用组件只能降级显示，不保证提供完整编辑体验，因此发布说明应提示不要用旧版本编辑含新功能的计划。导入/导出必须保留这些字段和子树内引用语义。

## 错误处理与并发

- 引用目标加载失败时只降级该引用组件，其他计划组件仍正常渲染。
- 引用目标变化时以稳定 ID 重新读取；过期路径只用于展示快照，不作为文件访问依据。
- 保存遵守现有 `updated_at` CAS；编辑器冲突时保留本地编辑内容，不以切换标签为由静默覆盖。
- Rename/delete 影响报告生成后若源文件或引用集合在确认前发生变化，执行时重新校验并要求重新确认，不基于过期影响集执行破坏性操作。
- 组件备注编辑状态、标签激活和引用聚焦均由单一状态源驱动；关闭/切库前先走当前保存与 flush 机制。
- 遇到权限错误、坏 JSON、断开的引用或索引扫描错误时给出可恢复反馈，不打印密钥或用户数据正文。

## 测试与验收

### 自动验证

- 类型/兼容性：旧版无 `plan_id`、无 `remark` 的计划能读取保存；可选字段清空后移除；未知或失效引用安全降级。
- 引用服务：按需分配稳定 ID、目标查找、反向索引刷新、移动/重命名保持身份、删除影响集、每条引用独立替换、取消和失败后目标保留。
- 安全：路径越界、损坏文档、库外 symlink/junction 不会被引用解析器读取；所有跨进程调用经正式 IPC 合约。
- 传输：导出/导入保留子树内部关系；与当前库 ID 冲突时重映射内部身份；外部缺失目标显示失效而不被错误绑定。
- 备注：所有组件类型（包括新引用组件）可增改清空备注；实时渲染内容、链接交互、Muya 按需挂载、CAS 冲突保留编辑内容。
- 标签：打开不重复、已有标签切换、关闭不删计划、重启恢复、库间隔离、rename/move 同步、无效项修复/跳过。
- 项目门槛：`npm run typecheck`、`npm run test`、`npm run build`；涉及 Windows 安装包时另按发布计划执行 `npm run build:win`。

### 用户视角验收

1. 从计划 A 普通关联跳到计划 B 和指定组件；重复点击树节点不生成重复标签。
2. 通过软链接在 A 查看 B 的某个原生组件；在 B 修改后 A 及时显示更新，点击“编辑原件”回到唯一的 B 原件，不出现重复拖动/删除控件。
3. 重命名目标时分别验证更新标签快照、保留旧显示和取消；移动目标后关联仍可打开。
4. 删除有多处引用的目标，验证逐条选择替代项、保留失效引用和取消三条路径；磁盘写入失败时目标不会继续被删除。
5. 在单选计划、任务列表、任务详情、注释、心情、标题、自定义组件和计划引用组件中分别增删 Markdown 备注，验证渲染与链接行为。
6. 在多个计划间切换、关闭标签、重启和切换不同计划库，确认活动状态恢复、内容不串库、关闭标签不会删除计划。
7. 在亮暗主题、窄窗口、键盘操作及系统减少动态效果下检查标签栏和引用卡片无裁切、遮挡或布局突跳。

## 非目标

- 不实现跨计划实时协同编辑、多人锁或云同步。
- 不让软链接成为第二份可编辑计划组件；不允许把引用组件本身再引用，避免递归图。
- 不支持指向其他计划库、任意文件系统路径或 Web URL 的软链接。
- 不扩展到每个 TaskItem 自带独立 Markdown 备注，不替换 Muya，不在所有卡片常驻创建编辑器。
- 不改顶部页面导航的布局或语义，不在左侧树中增加另一种标签栏。
- 不进行全库 `plan_id` 批量迁移，也不把引用索引作为唯一事实源。

## 实施拆分建议

三项属于一个用户体验批次，但按依赖拆成可独立验证的阶段：

1. 建立计划稳定身份、引用索引和 rename/delete 影响确认的主进程/IPC 基础。
2. 完成右侧多标签工作区、恢复与目标聚焦能力。
3. 集成普通关联与只读软链接组件，连接引用索引及工作区导航。
4. 为全部卡片加入按需 Markdown 备注，并完成三项联动回归和 Electron 视角验收。

每阶段的实际文件边界、执行者、任务镜像和 RED/GREEN 证据在用户批准本规格后另写入 `docs/Plan/` 执行计划及 `docs/HANDOFF-CURRENT.md`，当前均未开始。
