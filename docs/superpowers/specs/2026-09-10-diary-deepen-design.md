# 日记深化设计（日历回顾 / 统计趋势 / 记录顺滑 / 每日自动归档）

> 2026-09-10 · 由 brainstorming 流程产出（4 项用户决策 + demo 定稿，demo: `demo/diary-view-demo.html`）

## 1. 目标与用户故事

用户愿景：Trace 不只计划软件，也是日记软件。本批将日记做成一等公民：

- 作为日记软件，我能**回看**过去的每一天（月历热力 + 当日预览 + 时间线）
- 我能**洞察**心情趋势（本月均分 / 打卡天数 / 趋势连线）
- 我无需手动搭架子——每天自动生成日记页（**自动日计划**），打开就写
- 它是**计划的一个子域**：日记根可见可管理（树内普通节点），兼容拖拽/搜索/导入导出

## 3. 架构

四层结构无改动；新增两个单元：

- **main 服务** `diary-service.ts`：日记根的创建/盘点（幂等）与"今日页确保"，经 IPC `diary:ensure` 暴露
- **renderer 视图** `DiaryView.tsx`：月历/时间线/统计条/当日预览（纯组件，数据经 IPC 拉取）
- **顶栏导航**：顶栏新增「日记」切换钮，`ui-store` 增加视图态（`view: 'workspace' | 'diary'`）
- **树根**：`Diary` 根节点（特殊图标+蓝标），仍走现有 tree 服务懒加载

### 数据结构（契约零改动）

```
计划库根/
└── Diary/                       # 日记根（首次启动惰性创建；显示名「日记」）
    └── 2026-09-09/              # 日计划（目录名=日期，天然排序）
        ├── plan.json           # format_version:'1'，title=“2026-09-09”；components：模板三件套
        │                        #   heading“2026-09-09” + mood(score 50, mood_date=当天) + note“今日小结”
        └── （后续用户追加组件）
```

- 目录名 `Diary`（ASCII，路径安全/跨平台）；显示名「日记」（树/图标文案，i18n）
- 日计划 title = 日期字符串（`2026-09-09`）；与目录名一致
- **幂等守卫**：`ensureDiaryRoot`/`ensureTodayPage` 存在即跳过；绝不覆盖用户手改内容（只建不补）

## 4. 主流程（数据流）

```
应用启动/根目录切换 → diary:ensure（Diary 根存在？今日页存在？）→ 缺失则创建（模板三件套）
用户点顶栏「日记」→ ui-store.view='diary' → DiaryView 挂载 → IPC diary:month {year, month}
        → main 扫描 Diary/{yyyy-MM-dd}*（当月 28-31 个目录，树缓存/目录枚举）→ 返回 {date, score, notePreview, comps}[]
        → 月历/时间线/统计条渲染；点日期 → 当日预览（请求单页摘要）→「在树中打开」→ 恢复 view='workspace' + 树定位开卡（复用 search 回溯脉冲）
```

- 月历数据只取当月目录（31 次目录元信息读，无全库扫描）
- **统计口径（D4 定稿）**：均分/打卡/趋势 = 日记根下日计划内 mood 卡；`mood_date` 为空或缺失当日不计数（不把无记录天当 0）；均分=有记录日的平均

## 5. UI 规格（demo 定稿）

| 元素 | 规格 |
|---|---|
| 顶栏 | 「计划/日记/检索」导航钮；「日记」激活高亮；顶栏保持 no-drag 白名单 |
| 统计条 | 本月均分 · 打卡天数 · 记录条数 · 趋势迷你线（SVG 24px 高，端点圆点） |
| 月历 | 7 列（**周一起始**）；格=日期+心情色块+分数+组件数；今日蓝字高亮；未来灰置不可点；无记录日可点（显示空预览）；有记录日浅底 `--paper-dim` |
| 点日期 | 右侧切「当日预览」（心情/小结/组件摘要 + 「在树中打开」）；「← 返回时间线」回列表 |
| 时间线 | 右侧 300px 固定列；当月倒序：日期/彩色圆点(分数)/摘要首行 |
| 切换 | 左右切月；跨月数据/统计/趋势同步刷新 |

## 6. 边界与错误处理

- 日记根被用户改名/删除：`diary:ensure` 幂等重建（改名保留不了原名——重建仅当缺失；用户改名的 Diar 目录不动，仅确保 `Diary` 存在）
- 根目录切换：新库下重新 ensure；旧库不动
- 日期文件夹被用户手动改 title：审计不变（目录名=日期为真源）
- 搜索：日计划为普通计划 → 现有索引自动覆盖，零改动
- 空库引导兼容：`Diary` 是根文件夹之子目录，不冲突 BR-001
- 未来日期不允许写（日历置灰）；只保证今日及过去性

## 7. 测试计划

- `diary-service` 单测：ensure 幂等（重复调用不重建）/ 今日页内容契约 / 根切换重建 / 模板三件套断言
- 视图纯逻辑单测：月历网格生成（月首偏移/大小月）、统计聚合（均分/打卡/趋势点数；无记录日跳过）
- 契约零变更 → 无迁移、存量数据零改造

## 8. 非目标（YAGNI）

- 不做心情历史曲线之外的统计（周报/月报导出）
- 不做多日记本/标签系统
- 不做 mood 之外的“自动归档”类型（note 仅作模板占位）
- 不动树动效/搜索浮层既有行为
