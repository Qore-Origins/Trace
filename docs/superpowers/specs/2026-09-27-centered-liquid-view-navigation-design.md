# 顶栏居中胶囊式页面导航设计

日期：2026-09-27

状态：用户已选择 B「居中主导航」与 C「柔弹回落」，并选择子代理驱动。Task1–3 实现与独立审查完成；Task3 过冲修复提交 `a8e5e073858091b5ed985b213e24cf6e55f883b4` 的 scoped re-review Ready，无未解决 finding。当前进入 Task4 自动门槛及 Electron 实窗验收，具体状态见 HANDOFF-CURRENT.md。

## 背景与现状

Trace 顶栏同时放置「文件 / 编辑 / 查看 / 帮助」菜单和「计划 / 日记 / 回忆」页面入口。两组目前都是无底色的文字按钮，尺寸、颜色和激活方式相近，容易被看成同一种菜单。当前页面入口的无障碍名称还复用了「查看」菜单文案，语义也未区分。

顶栏高 48px，窗口最小宽度 720px。页面由 `ui-store` 中的 `view` 状态控制；`TopBar` 的 `ViewNav` 调用既有 `setView`，不涉及 IPC 或计划数据。当前页面入口样式仅给激活文字着色，没有共用轨道或滑块。

## 目标

1. 让页面导航在第一眼就与命令菜单区分开，并提升「计划 / 日记 / 回忆」的导航优先级。
2. 用居中大胶囊承载三个页面入口；切换时胶囊内的选中块呈柔弹液态移动，而不是瞬时跳变。
3. 保持现有路由状态、菜单行为、标题栏高度、搜索入口及窗口控制行为。
4. 在亮色/暗色主题、键盘操作、系统减少动态效果及 720px 最小窗口下仍清晰可用。

## 方案比较与决定

| 方案 | 区分度 | 代价 | 结论 |
|---|---|---|---|
| A：菜单后同栏分组胶囊 | 清晰，改动较小 | 页面导航仍靠近菜单组，中心感较弱 | 不采用 |
| B：顶栏中轴的主导航胶囊 | 页面切换成为明确主入口；菜单与页面导航分处不同视觉区域 | 顶栏需改为左 / 中 / 右分区；窄窗需压缩搜索区 | 采用 |
| C：独立第二导航带 | 菜单和页面导航的层级最明确 | 顶栏增加一行，压缩主内容垂直空间 | 不采用 |

页面导航位置采用 B；滑块运动采用用户在视觉稿中选定的 C「柔弹回落」。两项选择已经分别通过视觉稿交互与用户文字回复确认。

## 设计细节

### 顶栏布局

- 顶栏继续保持单行 48px，不新增第二行。
- 左区保留品牌与现有四个文字菜单；其菜单文字、下拉内容与操作不改。
- 中区把「计划 / 日记 / 回忆」放入约 226px 宽、42px 高的胶囊，并相对窗口水平中轴居中。
- 右区保留全局搜索和自绘窗口控制。窄窗时优先压缩搜索框，再使用已有的菜单间距收敛；胶囊、菜单和窗口控制不得重叠或被裁切。
- 页面入口保留现有中英文显示文案，不新增视觉标签、图标或第二套页面状态。

### 胶囊与状态

- 外轨使用现有主题 token 的中性表面、边框与圆角；活动滑块使用 `--trace-bg`，活动文字使用 `--link`，保证亮暗主题都不新增硬编码颜色。
- 未选中标签使用常规次级文字色。活动滑块明确占据一个完整分段，三个标签尺寸一致，点击区域覆盖整个分段。
- 页面状态唯一来源仍是 `useUiStore().view`。胶囊滑块位置、活动标签及 `aria-current="page"` 均由该状态派生，不创建第二份持久状态。
- 页面导航使用独立的本地化无障碍名称（中文「页面导航」、英文 “Page navigation”），不再借用「查看」菜单标签。

### 液态切换

- 点击目标标签后，`setView` 立即更新页面状态；胶囊滑块在胶囊内部朝目标段移动，带方向性的轻微横向拉伸和一次柔弹回落。
- 动效只作用于活动滑块和标签颜色，不液化页面内容，也不延迟页面导航状态。
- 动效以约 500–590ms 的单次过渡为设计范围，沿用现有 `--ease-spring` 运动曲线；连续切换时滑块从当前屏幕位置重新定向，不排队重放旧动画。
- 尊重 `prefers-reduced-motion: reduce`：取消拉伸/弹性过渡，状态仍立即切换。

### 无障碍与窗口交互

- 三个入口保持原生 `button`，顺序 Tab 可达，Enter / Space 激活，保留明显的 `:focus-visible` 轮廓。
- 更新中的 `aria-current="page"` 与视觉活动态一致；导航容器使用独立本地化名称。
- 新增元素继续属于标题栏的 no-drag 白名单；点击或键盘操作不得触发窗口拖拽。
- 不增加 hover 才能发现的功能，不改变双击标题栏最大化/还原行为。

## 架构与数据流

仅改渲染进程顶栏结构、顶栏样式、导航无障碍文案与相应测试。`ViewNav` 继续读取 `useUiStore().view` 并调用 `setView`；不改 `App` 页面分发、zustand 状态模型、IPC 合约、持久化数据或主进程服务。

视觉选中块由同一个当前 `view` 推导。任何纯动画瞬态仅限 CSS 展示，不作为页面状态或存储字段。

## 错误与降级

- 无异步请求或新增外部服务；切页与动效互不等待。
- CSS 动画不可用、偏好减少动态效果或快速重复点击时，仍立即切换到 store 指定的页面与标签，不得出现状态卡住或输入失效。
- 窄窗口不足以容纳搜索宽度时缩短搜索区；不得用裁切胶囊、隐藏菜单或覆盖窗口控制作为降级方式。

## 测试与验收

### 自动验证

- 组件测试验证三个按钮分别调用正确的 `setView`，页面状态变化后唯一活动态与无障碍名称正确。
- 样式契约验证页面胶囊与菜单使用独立视觉类、活动滑块过渡、`:focus-visible`、`prefers-reduced-motion` 与标题栏 no-drag 约束。
- 项目门槛：`npm run typecheck`、`npm run test`、`npm run build`。

### 用户视角验收

1. 在 720px 最小宽度和常用宽屏下确认胶囊精确居中，左侧菜单、右侧搜索和窗口控件不重叠。
2. 逐一点击、键盘激活计划 / 日记 / 回忆，确认活动块按 C 手感移动，当前页面和标签始终一致。
3. 快速连续切换时确认不会排队播放旧动画；启用系统减少动态效果后确认弹性动画退出但切换仍有效。
4. 在亮色和暗色主题下确认胶囊轨道、活动块、文本、边框和焦点轮廓可辨识。
5. 确认四个命令菜单、搜索入口、自绘窗口控制与标题栏拖拽行为未回归。

## 非目标

- 不重设计「文件 / 编辑 / 查看 / 帮助」菜单或其下拉层。
- 不新增页面、菜单、快捷键、图标或页面内容过渡动画。
- 不改变计划、日记、回忆页面的业务功能、路由语义或数据结构。
- 不改顶栏高度，不采用独立第二行导航。
