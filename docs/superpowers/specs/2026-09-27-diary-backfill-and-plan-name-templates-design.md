# 日记补建与计划命名模板设计规格

> 状态：用户已确认设计方向，规格待审阅；2026-09-27。
> 范围：应用内日记补建、未填写心情语义、按文件夹配置计划名称模板。
> 上位设计：本规格补充并覆盖 `2026-09-10-diary-deepen-design.md` 中关于启动确保、今日页模板和首次补建日期的旧行为描述。

## 1. 背景与目标

日记当前由 `DiaryView` 挂载时调用 `diary:ensure`，因此用户若未进入日记页，当天页面不会创建。旧模板预填 50 分，数字又会进入打卡与趋势统计，自动创建的空页面因此会被误当作真实心情记录。

计划创建对话框目前直接把输入内容作为目录名。用户需要在 `Daily_Plan`、`Future_Plan` 等文件夹里反复手动填写类型前缀和日期。

本功能应在不阻塞首屏、不覆盖用户文件的前提下补齐漏掉的日记，并允许每个计划父文件夹配置可复用的命名模板。

## 2. 用户可见行为

### 2.1 日记补建

- 计划库激活后，在窗口已显示的前提下异步检查日记；切换计划库时对新库执行同样检查。
- Trace 运行中跨过本地午夜时检查当天；系统睡眠后恢复或窗口重新获得焦点时再次检查。不得要求用户打开日记视图才触发。
- 首次运行新逻辑时：若存在有效日期日记，从最早的有效日期开始，逐日检查到今天并补建缺失日期；若没有有效日期日记，只创建今天。
- 首次补建完成后保存该库最后检查日期。后续检查从该日期之后继续补建，并始终确保今天存在。用户后来主动删除的、已经检查过的旧日期不自动复活。
- 补建按日期顺序幂等执行。崩溃或写入失败后重试，不覆盖已有 `plan.json`；已有日期目录中的其他文件保持原样。
- 新自动日记包含日期标题、未填写的心情卡和空白注释卡。未填写心情不显示为 50，不计入均分、打卡天数或趋势；用户输入有效分数后才计入。
- 空白自动日记仍可在日记日历/时间线中打开，但在用户填写心情分数、心情文字、注释内容或添加其他内容前，不进入「回忆」的历史、那年今日、里程碑和随机抽取，避免空白补建页被当作回忆。
- 仅影响新创建的空白日记。已有日记、已有心情值和历史统计均不迁移、不重写。
- 自动创建后刷新树、日历数据和搜索索引。日记创建失败不得阻止窗口显示或计划库使用；失败信息应可见，后续激活/聚焦时可重试。

### 2.2 计划命名模板

- 模板按**准确的父文件夹相对路径**配置并保存在当前计划库；切换计划库后加载对应库的规则。规则不自动继承到子文件夹，避免深层目录意外套用上层前缀。
- 模板只支持 `{date}` 与 `{title}` 两种占位符。`{date}` 为本地日期 `YYYYMMDD`；`{title}` 必须且只能出现一次。未知占位符或缺少标题占位符的模板不能保存。
- 新建计划对话框的目标父文件夹有模板时，输入框仅要求标题，并实时预览最终目录名。创建时使用相同模板格式化，并沿用现有文件名、重名和路径校验。
- 未配置模板的文件夹维持当前行为：输入完整计划名。重命名、文件夹创建、Markdown 导入不受影响。
- 内置默认规则：

| 父文件夹 | 模板 | 示例 |
|---|---|---|
| `Daily_Plan` | `Daily-Plan_{date}_{title}` | `Daily-Plan_20260927_心情不错` |
| `Future_Plan` | `Future_Plan-{date}-{title}` | `Future_Plan-20260927-Trace 改进` |
| `Weekly_Plan` | `Weekly_Plan_{date}_{title}` | `Weekly_Plan_20260927_本周安排` |
| `Short-Term_Plan` | `Short-Term_Plan_{date}_{title}` | `Short-Term_Plan_20260927_考试复习` |
| `Medium-Term_Plan` | `Medium-Term_Plan_{date}_{title}` | `Medium-Term_Plan_20260927_阶段目标` |
| `Long-Term_Plan` | `Long-Term_Plan_{date}_{title}` | `Long-Term_Plan_20260927_长期方向` |

- 设置中可为当前库的任意现有文件夹新增、修改或移除模板，并显示格式预览。设置说明延续项目约定，鼠标悬停 2 秒显示描述。
- 设置保存失败、模板无效、格式化后的计划名冲突时，显示具体错误；不创建部分计划。

## 3. 推荐方案与取舍

采用应用内后台补建和按库保存模板。自动化随 Trace 使用，不安装 Windows 计划任务或额外驻留服务；配置随计划库移动，避免不同库共享同一套命名规则。仅在日记页面懒创建会保留当前断档问题；操作系统级定时器会增加安装、权限和后台生命周期复杂度，超出“下次打开补建”的需求。

## 4. 数据与架构

### 4.1 日记

- 增加主进程协调逻辑，在窗口显示后的计划库激活、根目录切换、跨本地日期和恢复聚焦时调度 `diary-service` 的补建流程。首屏和根目录激活状态不得等待全量回填完成。
- 每日文件仍使用 `Diary/YYYY-MM-DD/plan.json`，遵守现有路径安全、原子写和 `PlanRepository.markInternalWrite` 约定。
- 新日记心情分数表示未填写。共享类型与心情卡需支持空值；用户输入数字后写入有效分数。日历聚合现有的数字型判断可排除未填写项，需通过服务与界面用例确认。
- 每库回填进度保存在 `.trace/diary-automation.json`。建议结构：`format_version: '1'`、`last_reconciled_date: string | null`。首次为 `null` 时扫描已有合法日期计划确定起点；成功完成当次区间后才前移水位。重复执行安全，文件损坏不能静默覆盖。
- 自写目录须抑制 watcher 回声；一批成功后使树缓存失效并发出计划变更事件，供树与搜索刷新。
- 根目录切换期间需避免旧库回填结果污染新库界面；每轮回填绑定启动时的根路径，切换后旧结果不得向当前窗口发送新库通知。

### 4.2 命名模板

- 通过现有主进程 IPC 边界读写当前库的 `.trace/plan-name-templates.json`；渲染进程不得直接访问文件系统。
- 模板配置以父文件夹相对路径为键，模板字符串为值。主进程校验路径、模板占位符和写入内容，并通过现有原子 JSON 写入能力保存。
- 在 shared 层提供纯格式化/校验规则，供设置预览和新建对话框共用；创建计划最终仍通过现有 `storage:createPlan`，由主进程再次执行路径安全与名称校验。
- 新建对话框打开时使用目标文件夹模板；所有现有创建入口复用同一 `NameDialogModal`，确保快捷键、菜单、树和空库引导行为一致。

## 5. 错误与边界

- 日期只使用本地日历日期；验证年月日真实性，覆盖闰年、跨月、跨年。
- 首次库没有历史日记时只生成今天，不能从空库建立任意长的回填区间。
- 对已有有效日期计划保持字节内容和组件不变；目录存在但尚无 `plan.json` 时，只新增该文件，不移除目录内其他内容。
- 每次写入失败保留未完成进度，后续重试从幂等流程恢复；窗口启动和计划库切换不因自动化失败而中断。
- 回填与模板配置均按计划库隔离；切根后不得沿用旧库模板或进度。
- 若配置文件格式无效，应报告错误并保留原文件供修复，不以默认空配置覆盖。

## 6. 验收标准

1. 从最早有效日记到今天的缺失日期被补齐；已有日期内容不变；空库仅创建今天。
2. 第一次回填中途失败后重试可完成，重复调用不重复覆盖；用户删除已检查的过去日期后，后续启动不自动重建该日期。
3. 新建日记的心情显示未填写，不参与日历均分、打卡天数或趋势；全空白补建页不进入回忆视图；加入实际记录后按已有规则参与；旧日记保持现状。
4. 应用窗口先显示，回填在后台进行；计划库切换后只对新库产生可见刷新。
5. 六种内置分类按表生成默认名称；自定义文件夹模板可保存、预览、修改、移除；未配置模板仍按旧方式命名。
6. 占位符、非法名称、重名和写入错误均可见且不留下半成品计划。
7. 主进程服务、IPC、设置存储、渲染组件和格式化逻辑具备自动化覆盖；实现完成后再运行项目规定的 typecheck、全量测试与 build，并做一次真实窗口的日记补建与模板创建验收。

## 7. 非目标

- Trace 关闭期间不运行系统计划任务，也不保证关闭时自动写文件；下次打开或恢复聚焦时补齐。
- 不重命名旧计划，不迁移旧日记分数，不重写用户已有 `plan.json`。
- 不做模板变量脚本、正则表达式、日期格式化语言或模板继承。
- 不改变任务、文件夹、导入导出和存储格式的既有语义。
