# 小沅智能体基础层设计规格

- 日期：2026-10-02
- 状态：待用户评审
- 阶段：智能体 Phase 1（基础层）
- 依赖：Trace 现有 Electron 主进程、IPC 合约与计划/日记读取服务
- 相关研究：[工具调用模式研究](../../research/2026-10-02-agent-tool-calling-patterns.md)、[国内模型 API 兼容性调研](../../research/2026-10-02-domestic-llm-api-compatibility.md)

## 1. 目标

建立小沅后续能力共用的本地模型接入和会话底座：用户可配置自己的 OpenAI-compatible Chat Completions 服务，在本地保存会话，以流式方式对话，并在每次外发前查看本次将发送的内容。通过无副作用测试验证具体服务配置能否正确返回流式原生工具调用，为后续计划操作能力提供准入依据。

本阶段只建设基础设施和普通对话，不让模型操作计划或文件夹；不实现偏好提取和日记润色。

## 2. 用户流程

### 2.1 配置模型服务

1. 用户在设置中创建一个具名服务配置，可从预设中选择或创建自定义 OpenAI-compatible 配置。
2. 预设填写经核验的 Chat Completions endpoint 与默认模型，API Key 留空；用户也可按供应商要求调整地址或模型。
3. 用户录入自己的 API Key。renderer 仅在输入过程中短暂持有；专用 IPC 交给 main 后立即清空输入状态。Key 不写入 renderer 持久化状态、localStorage、日志或会话。
4. main 使用 Electron `safeStorage` 异步接口加密保存 Key。若系统暂不可用，则只在 main 进程内存保存到本次应用会话结束，并明确提示用户关闭应用后需重新输入；禁止明文落盘。
5. 已保存 Key 只显示“已配置”，允许替换或移除，不提供读取/复制已保存 Key 的接口。移除 Key 不删除服务配置。
6. 用户可保存多个 profile，设置默认 profile，并在单次会话选择其他 profile。

首批预设分组：国内直连的阿里百炼、DeepSeek、Kimi、火山方舟、硅基流动、百度千帆；聚合服务单列腾讯云 TokenHub；保留自定义 OpenAI-compatible。尚未完成官方核验的 GLM、MiniMax、ModelScope 等不进入首批目录。Coding Plan 专用地址不作为通用预设。预设只代表连接参数已预填，不代表模型已支持工具调用。

### 2.2 普通会话与外发预览

1. 用户新建或打开本地会话，选择当前使用的 profile。
2. 用户编写消息；可以按需选择若干具体计划或日记条目作为本次上下文。默认不选择任何计划或日记；文件夹只用于浏览，不递归勾选或附加其子项。
3. 发送前显示本次外发预览，至少包含：目标供应商/profile/模型、用户消息、将带出的同会话历史、选中计划/日记的准确内容及版本标识、已审核的偏好（Phase 3 才提供）。会话历史默认纳入本会话后续请求，但用户可在这次预览中排除；尚未实现的偏好项不显示。
4. 用户可在预览中取消单项上下文或取消发送。取消时不得发起 provider 请求。
5. 确认后由 main process 发请求，助手文本通过 SSE 渐进显示。用户每次新消息或显式重试都重新预览；不跨会话自动附带旧会话历史。
6. 会话默认保存在本地，用户可删除会话。聊天记录和溯源数据不上传到 Trace 服务（Trace 不提供云端会话服务）。

本阶段上下文选择只附加用户明确勾选的计划/日记条目正文，不附加其关联对象、整库索引、无关文件或文件夹下的所有内容。发送给模型的是预览所展示的同一份内存快照；快照在请求结束后不作为额外副本持久化。会话本地溯源保存所选对象标识与当次版本标识，不复制保存其正文。

### 2.3 主动能力测试

1. 用户在某个 profile 上主动启动“测试工具调用能力”；开始前提示外部请求可能产生费用。
2. 请求只含最小合成对话与一个无副作用工具定义，不带计划、日记、会话历史、偏好或密钥内容。
3. 测试验证流式响应是否完整收束、是否能按 index 正确合并 `tool_calls` 增量、工具名与参数是否符合测试 schema。探测工具永不执行。
4. 结果显示为未测试、通过、失败或需重测，并记录时间与脱敏错误类别。通过仅表示该 profile 最近一次测试通过，不表示所有模型能力永远可用。
5. API 地址、协议、模型或 API Key 新增/替换/移除后，测试状态失效并标为需重测。能力失败不阻止普通聊天；Phase 2 计划工具只能在 profile 测试通过后开放。

### 2.4 流式中断

- 用户主动停止生成时，将该轮标注为 `【用户中断】`；连接、provider 或应用等非主动中断标注为 `【异常中断】`。已经显示的助手文本保留在本地会话并标记对应类型，不得伪装为完整答复。标注是独立的会话状态/历史占位符，不改写原始助手文本，也不伪装成用户输入。
- 后续模型请求默认不带入该轮半截正文，但会在会话历史/外发预览中以相应占位符标注中断类型，让用户和模型都能区分中断来源。用户可在新的外发预览中明确选择是否连同半截正文一起带入；占位符随会话历史发送时也必须在预览中可见，且作为独立、清楚标识的历史项序列化。
- 未完整收流的工具调用增量不得保存为可执行调用；只保留中断、未执行状态。
- provider/网络错误不自动重试。用户显式重试时视为新请求，重新预览外发内容。

## 3. 功能范围

### 本阶段包含

- OpenAI-compatible Chat Completions 协议适配；文本 SSE 流式输出。
- 多 profile、默认 profile、单会话 profile 选择及用户自管 API Key。
- 本地聊天记录、删除会话、会话来源信息和所选上下文版本标识。
- 每次发送前的准确外发预览和逐项取消授权。
- profile 级、用户主动触发的合成流式 `tool_calls` 能力测试。
- 后续阶段所依赖的 typed provider adapter、main-process 会话服务、受限 IPC 和本地溯源数据边界。

### 明确不包含

- 计划/文件夹创建、编辑、移动、重命名、删除等工具执行。
- `@` 目标解析及读写权限模式。它们属于 Phase 2 规格；相关已确认原则见 HANDOFF。
- 偏好自动提取、审批、提示词注入和日记润色，属于 Phase 3。
- Responses API、Anthropic Messages、供应商原生协议及 JSON 文本工具调用回退。
- Shell、任意文件读写、动态插件、MCP、通用代码编辑器或云端会话同步。
- 在正常聊天请求中提供可执行工具。除能力测试外不向模型传工具定义；即便异常收到工具调用也必须拒绝执行。

## 4. 服务商与传输约束

- 通用协议只实现 OpenAI Chat Completions 与原生结构化 `tool_calls`；不因兼容性差异回退到解析普通文本 JSON。
- 服务商差异放在 profile 配置/typed adapter 边界，不将供应商扩展字段混入通用请求。首批目录以 Trace 静态维护的官方核验结果为准；实施前复核 endpoint、默认模型和官方链接。
- 远端 endpoint 必须使用 HTTPS；HTTP 仅允许 loopback 本机服务。首发不允许局域网明文 HTTP。
- 预设不得包含凭据。默认模型或地址需要地区、Workspace、部署 ID 等额外配置时必须明确提示，不能承诺只填 Key 就必然可用。
- main process 独占 provider 网络请求、凭据访问和能力状态变更；renderer 仅通过 `shared/ipc-contract.ts` 中的窄类型接口交互。

## 5. 架构边界

沿用已批准的 Electron 主进程集成方式，按需惰性初始化 agent service，优先让应用窗口启动，不增加独立 sidecar。建议职责分离如下；具体类名与存储技术留给实现计划，不在本规格锁定：

- profile 配置：非密钥服务字段与 Key 状态；renderer 永远不能读取解密后的 Key。
- 凭据：main-process 安全存储，安全存储不可用时使用会话内存降级。
- provider adapter：构建 Chat Completions 请求、发送 SSE、将流转换为内部文本/工具增量事件。
- conversation repository：本地会话、消息、不完整状态与阶段 1 溯源信息。
- context snapshot / outbound preview：收集本次用户明确选择的内容，生成预览快照；未经确认不调用 provider。
- capability tester：合成测试单独构造请求，不共享真实会话上下文，不调度或执行探测工具。
- IPC：在 shared 合约中定义 profile、会话、预览、发送、取消/中断和测试结果所需的 typed 请求/响应；renderer 不直接访问 fs、Electron API 或 provider。

## 6. 本地数据与隐私

- 本地保存 profile 元数据、会话消息、中断类型标记、profile/模型标识、请求时间、用户选择的计划/日记 ID 与版本标识、能力测试的状态/时间/脱敏错误类别。
- 不保存 API Key 明文；不把 Key 写入日志、错误消息、聊天记录、测试快照或 Git。
- 不持久化原始 HTTP 包。为满足准确外发预览与会话追溯，当前请求上下文快照仅在发送前/请求期间保留于内存；完成后只保留来源标识与版本，不重复保存源正文。
- 用户删除会话时，删除该会话消息及其会话级溯源记录；不影响 profile 与 Key。
- Phase 1 不新增遥测、云端历史或后台静默上传。

## 7. 失败与安全行为

- 所有 provider 响应均视为不可信输入；验证 SSE 事件结构、（若响应提供）消息 ID 一致性、工具调用 index、工具名和 JSON 参数，不把非关键可选字段缺失当成通用兼容失败，也不因解析失败执行任何动作。
- 对响应流按 index 累积 tool-call name/arguments；仅在完整收流后解析并校验。本阶段只用于能力测试；测试工具无副作用且不被执行。
- 未授权、取消、预览版本失效或 provider 错误均不得发送未批准的上下文。重试必须重新预览。
- 预览确认到实际发出间若本地源对象版本改变，应中止本次请求并要求重新预览，避免预览内容与实际外发内容不一致。
- 错误信息对用户可读且脱敏；不得包含 Key、完整请求头或原始凭据。日志仅记录排障所需的安全类别，不记录消息正文或上下文正文。
- 服务初始化和 provider SDK 加载不得阻塞 Electron 窗口启动。

## 8. 验收标准

1. 选择首批预设可看到已核验的协议、地址和默认模型，API Key 为空；自定义配置可编辑 endpoint 与模型；多个 profile 可保存、切换和设默认。
2. Key 输入经专用 IPC 到 main 后 renderer 表单值立即清空；已保存 Key 无读取接口；safeStorage 不可用时给出明确会话内存提示且不产生明文文件。
3. 远端 HTTP endpoint 被拒绝，HTTPS 可配置；loopback HTTP 可配置；局域网 HTTP 被拒绝。
4. 新建会话默认无计划/日记上下文；逐条勾选后预览显示确切内容与版本；取消发送后 provider mock/测试服务器收不到请求；确认后收到内容与预览完全一致。
5. 同会话历史默认进入后续请求的预览，用户可以排除；新会话不携带旧会话历史。主动停止与非主动中断分别显示 `【用户中断】` / `【异常中断】`；后续预览默认只带相应占位符、不带半截正文，用户主动选择后才连同正文带入。
6. 正常聊天文本按 SSE 逐步显示；取消/断流后保留已显示文本并标注中断；错误不会自动重试。
7. 能力测试只发送合成消息与探测 schema，不携带用户数据、不调用探测工具；合法流式原生调用通过，畸形/不完整调用失败且不执行。
8. profile 的 endpoint、协议、模型或 Key 变化都会使测试状态失效；失败测试仍可普通聊天。
9. 检查本地会话记录和日志中没有 API Key、原始 HTTP 请求包或额外复制的计划/日记正文；删除会话不删除 profile。
10. 主进程服务惰性初始化，应用窗口启动流程不等待 provider 或 agent 服务。

实现阶段对主进程 IPC、配置/密钥存储、上下文授权和 SSE 累积补充回归测试，并按项目要求运行 `npm run typecheck` 与 `npm run test`；真实 provider 连通性由用户在自己的配置与 Key 下主动验证，自动化测试不得依赖真实密钥或外部 API。

## 9. 后续阶段依赖

- **Phase 2：计划操作智能体**。复用本阶段 profile、stream、conversation、context preview 和 provenance 底座；另行规格定义 `@` 单目标、计划/文件夹工具白名单、权限模式、CAS、影响预览、确认/撤销、序列化执行与循环上限。不得把本阶段的能力测试等同于计划工具授权。
- **Phase 3：个人化**。另行规格定义经用户审核后保存的偏好候选、逐次外发预览中的偏好授权、日记润色强度、差异比较及用户明确采用后写回。

## 10. 实施前留白

以下属于实施计划/技术选型，不改变本规格已经确认的用户可见行为：本地会话数据采用现有存储设施还是单独存储层、具体 profile schema 版本策略、请求超时值和 SSE 缓冲上限、具体 provider SDK/HTTP 客户端、设置与会话界面的组件拆分。实施计划必须给出选择及依据；密钥明文落盘、静默外发、渲染进程直连 provider 等不属于可选方案。
