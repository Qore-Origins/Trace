### 3. 技术栈与工程画像定案

**如何使用**：技术选型报告定案：桌面壳 Electron 44（Node 24.18.1/Chromium 152）+ 渲染器 React 19 + TypeScript 5 + antd 5；无后端、无数据库（明文件 JSON + 进程内缓存/索引）；分发电子 builder NSIS；CI GitHub Actions。

**利弊分析**：
- 利：Web 技能直接复用；明文件/可迁移性最优；多端（macOS/Linux）同代码可发。
- 弊 / 权衡：Electron 包体 80-120MB、内存较高（个人工具可接受）；需跟随 8 周一版升级节奏（≤1 版延迟承诺）。

**改动细节**：
- `docs/lifecycle/02-系统设计 Design/技术选型报告 Tech Stack.md` — 新建（候选矩阵计权：Electron 4.25 / Tauri 3.75 / Flutter 3.85 / 原生 3.80）
- `docs/lifecycle/02-系统设计 Design/架构设计文档 Architecture.md` — 新建（渲染/主进程/数据三层；ADR-001~006；工程基线 EB-01~06）

### 4. 存储格式契约 v1（代替数据库）

**如何使用**：数据=用户指定计划库根目录的明文件：每计划一文件夹 + `plan.json`（组件序列），`.trace/plan-library.json` 为库元数据；版本化迁移规则（附录C）；所有写入走原子写（tmp→fsync→rename）。

**利弊分析**：
- 利：整库拷贝即备份；任意工具可读；崩溃无半写；语义迭代不丢数据。
- 弊 / 权衡：无数据库事务/查询；一致性靠"原子写 + 索引最终一致（≤1s）"。

**改动细节**：
- `docs/lifecycle/02-系统设计 Design/数据库设计说明书 DB Design.md` — 新建（契约 v1：目录布局/字段表/JSON Schema/索引策略/迁移规则/测试用例 TC-01~06）

### 5. IPC 白名单接口契约 v1

**如何使用**：渲染进程只经 preload 暴露的 20 条通道与主进程通信（`app.*/storage.*/search.*/config.*`），统一 `TraceResult` 信封，错误码 10-50，事件通道 `trace:*`，含 CAS 防冲突（code 22）。

**利弊分析**：
- 利：安全边界明确（contextIsolation/sandbox）；类型同源（src/shared 契约）。
- 弊 / 权衡：新增能力需先注册通道（小成本）；调试跨进程（DevTools 双开）。

**改动细节**：
- `docs/lifecycle/02-系统设计 Design/接口设计文档 API Design.md` — 新建（通道全表/载荷/错误码/事件）
